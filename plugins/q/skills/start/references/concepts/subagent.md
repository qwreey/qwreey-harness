# subagent — 따로 일하고 결과만 가져오는 보조 Claude

> 한 줄: subagent 는 **자기 책상(컨텍스트)을 따로 가진 보조 Claude** 다. 지저분한 조사를 거기서 하고, 내 책상에는 요약만 가져온다.

## 쉽게 말하면
- 팀장(메인 Claude)이 조수에게 "창고 가서 빨간 상자 몇 개인지 세 와" 라고 시키는 것과 같다.
  조수는 창고를 다 뒤지지만, 팀장 책상에는 "빨간 상자 12개" 한 줄만 올라온다.
- 조수는 **시킨 말만 안다.** 팀장과 나눈 대화를 모른다. 그래서 지시가 분명해야 한다.

## 왜 쓰나 (context 분리의 장점)
1. **내 책상이 깨끗하다.** 큰 파일 읽기, 긴 로그, 검색 결과가 메인 대화를 채우지 않는다.
2. **동시에 여러 일.** 서로 상관없는 조사 두세 개를 나란히 돌릴 수 있다.
3. **선입견 없는 눈.** 새 책상에서 보니까 리뷰·검토에 좋다. 내 가설을 같이 건네면 그 장점이 사라진다.
4. **권한 제한.** 읽기만 하는 조수(예: 내장 Explore)를 쓰면 실수로 고칠 일이 없다.

## 비용과 주의
- 조수도 **자기 몫의 요청을 따로 보낸다.** 내 사용량 한도에서 같이 빠진다. 조수를 많이, 오래 돌릴수록 사용량이 그만큼 는다.
- 결과가 길면 그 결과가 다시 내 책상을 채운다.
- 실제로 subagent 를 많이 띄워 하루에 수백 달러가 나간 사례가 있다(이 하네스 운영 기록). 한 번에 여러 개를 띄울 땐 먼저 묻게 하자.
- 비싼 모델로 돌 필요 없는 조사는 더 싼 모델을 쓰게 할 수 있다. 단 쓰기·판단이 남는 일은 너무 작은 모델에 맡기지 않는다.

## 언제 쓰고 언제 안 쓰나
| 쓴다 | 안 쓴다 |
|---|---|
| "이 함수가 어디서 쓰이는지 전부 찾아 줘" | 파일 하나 열어 보면 되는 일 |
| 긴 로그에서 오류만 추려 오기 | 이미 답을 아는 확인 |
| 독립적인 조사 2~3개 동시에 | 서로 결과가 필요한 순서 있는 일 |
| 내가 짠 코드를 새 눈으로 리뷰 | 대화 맥락이 꼭 필요한 일 |

## 직접 해 보기
- "subagent 를 써서 이 폴더에서 Sound 를 쓰는 스크립트를 찾아 줘. 결과는 파일 경로만." 처럼 시킨다.
- 사람이 만든 subagent 정의는 `.claude/agents/`(프로젝트)와 `~/.claude/agents/`(나 전체)에 있다. "지금 쓸 수 있는 subagent 종류 알려 줘" 라고 물어봐도 된다.
- `/usage` 의 사용량 분해에서 subagent 몫을 볼 수 있다.

## 흔한 오해
- "subagent 는 공짜 일꾼" → 아니다. 각자 토큰을 쓴다.
- "조수가 내 대화를 다 안다" → 모른다. 필요한 정보는 지시에 담아야 한다.

## 이해 확인 질문 (설명 뒤 하나만 골라 묻는다)

- subagent 는 내가 메인 대화에서 한 말을 알까요? (답: 모른다)
