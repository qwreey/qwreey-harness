# auto mode — 허락 질문 대신 "검사 모델" 이 지키는 모드

> 한 줄: auto mode 에서는 Claude 가 매번 묻지 않고 일한다. 대신 **별도의 검사 모델(분류기)** 이 위험한 행동을 골라 막는다. 안전을 보장하지는 않는다.

## 권한 모드 한눈에
| 모드 | 어떻게 동작하나 |
|---|---|
| Manual (`default`) | 파일 수정, 명령 실행, 인터넷 접근 대부분을 **나에게 묻는다** |
| accept edits | 파일 수정은 묻지 않고, 명령 등은 묻는다 |
| plan | 읽고 계획만 세운다. 고치지 않는다 |
| **auto** | 묻지 않는다. 검사 모델이 위험한 것만 막는다 |
| bypass permissions | 거의 아무것도 묻지도 막지도 않는다(위험) |
- `Shift+Tab` 으로 모드를 돌아가며 바꾼다. 화면 아래 상태줄에 지금 모드가 보인다(`⏵⏵ auto mode on` 등).
- 최근 버전(v2.1.283 이상)은 터미널·VS Code 에서 **auto 로 시작하는 게 기본**이다. 회사가 관리 설정으로 끄거나 기본 모드를 바꿀 수 있다.

## 검사 모델이 하는 일
1. 내 허용/거부 규칙에 걸리면 그대로 처리한다(거부 규칙은 어느 모드에서나 막는다).
2. **작업 폴더 안의 읽기와 파일 수정은 검사 없이 통과**한다(일부 보호된 경로 빼고).
3. 나머지(명령 실행, 인터넷, 폴더 밖 등)는 검사 모델이 본다. 막으면 Claude 에게 이유가 전달된다.

## 기본으로 막는 것 (예)
- 인터넷에서 받은 코드를 바로 실행(`curl ... | bash`)
- 민감한 데이터를 바깥으로 보내기, 비밀(토큰·키)을 화면이나 파일에 출력하기
- 세션 전부터 있던 파일을 되돌릴 수 없게 지우기, 강제 push, `git reset --hard` 류
- 운영 배포, 클라우드 대량 삭제, 권한 부여, 공용 인프라 변경
- 공개 저장소에 비밀·내부 자료 올리기, 내가 지목하지 않은 외부 저장소에 PR·push
## 기본으로 허용하는 것 (예)
- 작업 폴더 안 파일 작업, 잠금 파일에 적힌 의존성 설치, 읽기 전용 웹 요청, 작업 중인 저장소로 push

## 그래서 "동의" 가 따로 필요하다
- auto mode 는 **작업 폴더 안 파일을 묻지 않고 고친다.** 위험 행동은 막아도 "내가 원한 수정인지" 는 묻지 않는다.
- 또 auto mode 는 Claude 가 확인 질문 없이 계속 진행하도록 유도한다. 단 **프롬프트나 스킬이 묻는 데 의존하면 묻는다.**
- 그래서 회사는 "파일 쓰기·설정 변경·설치·외부 전송 전에는 설명하고 동의받는다" 는 지시를 CLAUDE.md 에 둔다. 이 지시는 권고라서 100% 는 아니므로, 꼭 막아야 하는 것은 회사 관리 설정(ask/deny 규칙)으로 막는 것이 정석이다.

## 이렇게 하면 좋다
- 처음엔 auto 로 두되, 중요한 폴더에서는 Manual 로 바꿔 하나씩 보자(`Shift+Tab`).
- 질문 창이 뜨면 **무엇을, 어디에** 하는지 읽고 누른다. 습관적으로 "예" 를 누르지 않는다.
- "막혔다" 는 메시지가 나오면 우회하라고 시키지 말고 왜 막혔는지 물어본다.

## 흔한 오해
- "auto = 안전" → 공식 문서: 질문을 줄일 뿐 안전을 보장하지 않는다.
- "auto 는 아무것도 안 묻는다" → 명시적 ask 규칙, 질문 도구, 일부 위험한 삭제는 여전히 묻는다.

## 이해 확인 질문 (설명 뒤 하나만 골라 묻는다)
- auto mode 에서 작업 폴더 안 파일 수정은 누가 허락하나요? (답: 검사 없이 통과)
- 그래서 회사가 따로 '동의' 지시를 두는 이유는?
