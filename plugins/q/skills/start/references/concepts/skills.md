# skills — 필요할 때 꺼내 쓰는 작업 설명서

> 한 줄: 스킬은 **"이 일은 이렇게 해" 를 적어 둔 폴더**다. 평소엔 이름과 한 줄 설명만 보이고, 쓸 때만 본문을 읽는다.

## 쉽게 말하면
- 책장의 매뉴얼이다. 책등(이름·설명)은 늘 보이지만, 책을 펴는 건 필요할 때뿐이다.
- 그래서 긴 지식·절차를 CLAUDE.md 대신 스킬에 두면 평소 비용이 적다.

## 부르는 두 가지 방법
1. **내가 부른다:** `/스킬이름` (예: 지금 쓰는 `/q:start`). 플러그인 스킬은 `/플러그인:스킬` 로도 부른다.
2. **Claude 가 알아서 부른다:** 설명(description)을 보고 맞는 상황이면 스스로 읽는다.
   - 단, **알아서 부르는 건 보장되지 않는다.** 외부 평가에서는 절반 넘게 안 부른 사례도 있었다(조건이 한정된 결과). 중요할 땐 이름으로 직접 부르자.

## 생김새
```
my-skill/
├── SKILL.md        ← 맨 위에 name, description. 아래 본문(절차)
├── references/     ← 필요할 때만 여는 자세한 설명
└── scripts/        ← 함께 쓰는 스크립트
```
- 위치: 프로젝트 `.claude/skills/`, 내 전체 `~/.claude/skills/`, 또는 플러그인 안.

## 알아 두면 좋은 설정
| 설정 | 뜻 |
|---|---|
| `disable-model-invocation: true` | **사람만** 부를 수 있다. 부작용 있는 절차(배포, Studio 쓰기, 이 온보딩)에 쓴다 |
| `user-invocable: false` | `/` 메뉴에 안 보이고 Claude 만 쓴다(배경 지식용) |
| `allowed-tools` | 그 스킬이 도는 턴에 묻지 않고 쓸 도구. 함부로 넓히지 않는다 |
| `description` | Claude 가 언제 쓸지 고르는 근거. 1,536자에서 잘린다. 핵심을 앞에 |

## 비용과 주의
- 스킬 이름·설명은 **항상** 책상에 오른다. 스킬이 수십 개면 그것만으로 자리를 꽤 쓴다. 안 쓰는 스킬은 끈다.
- compact 뒤에도 실행했던 스킬 본문은 다시 들어가지만 크기 제한이 있어 앞부분만 남을 수 있다. 중요한 지시는 위쪽에.
- 남이 만든 스킬은 스크립트를 실행할 수 있다. **출처를 믿을 수 있을 때만** 설치한다.

## 직접 확인하기
- `/skills` : 쓸 수 있는 스킬 목록. `t` 를 누르면 토큰(비용) 순으로 정렬된다.
- `/skill-doctor` : 스킬마다 비용과 얼마나 쓰였는지 (버전·설정에 따라 없을 수 있다).

## 흔한 오해
- "스킬을 많이 깔수록 똑똑해진다" → 설명이 상시 비용이고, 비슷한 스킬끼리 헷갈려 엉뚱한 걸 고르기도 한다.
- "스킬에 써 두면 알아서 쓴다" → 보장되지 않는다. 이름으로 부르거나 CLAUDE.md 에 "이럴 땐 /이름" 색인을 짧게 둔다.
