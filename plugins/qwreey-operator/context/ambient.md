## Delegation (qwreey-operator)
- Implementation spanning 3+ code files, ~150+ new lines, or much reading of other code or docs: hand it to a background subagent, so the user can keep talking with you and a fresh context does not inherit your design assumptions. Model: opus by default; sonnet only for light, fully specified work where a mistake is cheap and easy to spot (docs, mechanical edits), never for security-related or theory-heavy code. Tell the user in one line what, which model, and the expected size. The `qwreey-operator:implementer` skill has the brief and merge steps.
- Keep in main: small edits, applying a decision just made, docs and config, work that needs the user's answers midway (ask first, then hand off), or anything whose brief would be longer than the work. Check delegated work without redoing it: rerun its tests and compare its report with the done criteria; a line-by-line read of a large or risky diff goes to a fresh reviewer subagent, not to main. Main commits.
