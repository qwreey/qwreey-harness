## Delegation (qwreey-operator)
- Implementation spanning 3+ code files, ~150+ new lines, or much reading of other code or docs goes to a background subagent (a fresh agent, not a fork), not main, so the user can keep talking with you and a fresh context does not inherit your design assumptions. Keep small edits, a decision just made, docs and config, and work that needs the user's answers midway in main. Tell the user in one line: what, which model, expected size.
- Implementer model: opus by default; sonnet only for light, fully specified work where a mistake is cheap and easy to spot, never for security-related or theory-heavy code.
- Beyond the usual brief: quote the user's own words, give done criteria with the test command, and ask for a report of changed files, test output and open questions (so it does not settle ambiguities silently). If main may touch the same files meanwhile, launch it with `isolation: "worktree"`: it commits on its worktree branch and main merges that branch and removes the worktree. Otherwise it must not commit.
- Check without redoing: rerun its tests and compare the report with the done criteria; open a file only where the report is vague or the tests do not reach. A large or risky diff goes to a fresh reviewer subagent; reproduce each finding before acting on it. Main commits.
