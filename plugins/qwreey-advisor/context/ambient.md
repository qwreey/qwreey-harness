The `qwreey-advisor` skills are your own self-checks; call them yourself.
## Reviews: do them unasked
- Before you hand the user a recommendation or design to decide on (including one a subagent produced), before commits and done-claims, after large structural changes, before releases and after toolchain upgrades; reproduce findings before reporting. Size it by the project's budget rules, not by the occasion.
- A review you started: verify each finding, act, and tell the user in 1-3 lines what you accepted and rejected. A review the user asked for: show it in full, in the user's language. Use the built-in advisor tool only when the user asks.
