# session — 대화 한 판

> 한 줄: session 은 **한 폴더에 묶인 저장된 대화**다. 끝내도 기록이 남아 이어 할 수 있고, `/clear` 로 새로 시작할 수 있다.

## 쉽게 말하면
- 노트 한 권이라고 생각하자. `/clear` 는 새 노트를 펴는 것이다. 예전 노트는 버리지 않고 책장에 꽂힌다.
- 노트(대화 기록, 트랜스크립트)는 내 컴퓨터에 파일로 저장된다: `~/.claude/projects/<폴더 이름>/<세션 id>.jsonl`
- 세션은 **시작한 폴더**에 묶인다. 같은 프로젝트 폴더에서 열어야 이어 하기 목록에 보인다.

## 자주 쓰는 명령
| 하고 싶은 것 | 명령 |
|---|---|
| 방금 하던 대화 이어 하기 | `claude --continue` |
| 목록에서 골라 이어 하기 | `claude --resume` 또는 대화 중 `/resume` |
| 새 대화로 시작(이전 것은 저장됨) | `/clear` (`/clear 이름` 이면 이전 대화에 이름을 붙여 둔다) |
| 나중에 찾기 쉽게 이름 붙이기 | `/rename 이름` |
| 일부만 되돌리거나 요약 | `/rewind` |

## 이어 하면 무엇이 돌아오나
- 대화 내용, 모델, (터미널에서 이어 할 때) 권한 모드가 돌아온다.
- 시작할 때 붙였던 일부 옵션(`--plugin-dir`, `--add-dir` 등)은 **다시 붙여야** 한다.
- 중간에 끊긴 명령은 다시 실행되지 않는다.

## 세션 구성 요령
1. **한 일 = 한 세션.** "버튼 아이콘 정리" 가 끝나고 "사운드 이름 바꾸기" 로 가면 `/rename` 후 `/clear`.
2. 길게 이어 갈 일이면 진행 상황을 파일에 적어 두게 한다(쓰기이므로 동의 후). 다음 세션은 그 파일만 읽으면 된다.
3. 같은 파일·같은 Studio 를 **두 세션이 동시에 고치지 않게** 한다. 서로 덮어쓴다.
4. 오래 열어 둔 세션은 쉬었다 돌아온 첫 메시지가 비싸다(캐시가 식어 전체를 다시 읽음). 새 일이면 새 세션이 싸다.

## 기록 파일은 민감하다
- 트랜스크립트에는 대화, 열어 본 파일 내용, 명령 결과가 **그대로** 남는다. 비밀번호·키를 붙여 넣지 말자.
- 기본 30일 뒤 자동으로 지워진다(`cleanupPeriodDays` 설정, 바꾸려면 동의 필요).
- auto mode 는 Claude 가 트랜스크립트 파일을 고치는 것을 막는다. 읽기는 막지 않는다.

## 흔한 오해
- "`/clear` 하면 다 날아간다" → 저장돼 있다. `/resume` 으로 돌아간다.
- "창을 닫으면 끝" → 기록은 남는다. 30일 안에는 이어 할 수 있다.
- "세션을 길게 유지할수록 똑똑해진다" → 반대인 경우가 많다. → `context.md`

## 1분 실습
1. `/rename 온보딩` 으로 이 대화에 이름을 붙인다.
2. 나중에 `claude --resume` 을 실행하면 목록에 "온보딩" 이 보인다.

## 이해 확인 질문 (설명 뒤 하나만 골라 묻는다)
- `/clear` 하면 이전 대화는 어떻게 되나요?
- 트랜스크립트에 비밀번호를 붙여 넣으면 왜 위험한가요?

## 근거
- 공식: code.claude.com/docs/en/sessions (--continue, --resume, /resume, 복원 항목, 트랜스크립트 위치)
- 공식: settings-reference `cleanupPeriodDays` (기본 30)
- 공식: costs ("Use /rename before clearing", "Cache misses")
- 공식: permission-modes (auto mode 가 트랜스크립트 쓰기를 막음)
