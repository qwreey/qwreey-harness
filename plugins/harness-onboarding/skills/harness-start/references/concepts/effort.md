# effort — 얼마나 깊이 생각할지 정하는 다이얼

> 한 줄: effort 를 올리면 더 깊이 생각하지만 **느리고 비싸진다.** 내리면 빠르고 싸다. 기본값으로 충분한 일이 대부분이다.

## 쉽게 말하면
- 같은 사람에게 "대충 봐 줘" 와 "꼼꼼히 따져 봐" 를 고르는 것이다. 모델이 바뀌는 게 아니라 생각하는 양이 바뀐다.
- 단계: `low` → `medium` → `high` → `xhigh` → `max` (모델마다 쓸 수 있는 단계가 다르다)
- 최신 모델(Opus 5.5, Sonnet 5.5, Haiku 5.5 등)의 기본은 `medium` 이다.

## 바꾸는 법
| 방법 | 효과 |
|---|---|
| `/effort` | 고르는 창이 뜬다. Enter 는 기본값으로 저장, `s` 는 이번 세션만 |
| `/effort high` | 바로 지정 |
| 메시지에 `ultrathink` 라고 쓰기 | **그 한 번만** 더 깊이 생각 |
| `max` | 가장 깊다. 보통 이번 세션에만 적용된다 |
| 스킬 설정 `effort:` | 그 스킬이 도는 턴만 |
- 회사가 상한을 걸 수 있다(관리 설정 `maxEffortLevel`). 상한보다 높게 고르면 상한으로 돈다.

## 언제 올리나, 언제 내리나
- 올린다: 원인 모를 버그, 여러 파일이 얽힌 설계 결정, 한 번 틀렸던 문제를 다시 볼 때 → `ultrathink` 로 그 한 번만.
- 내린다: 이름 바꾸기, 목록 정리, 문장 다듬기, 단순 질문.
- **effort 는 모호한 요청을 고쳐 주지 않는다.** "알아서 잘" 을 `max` 로 돌려도 무엇을 원하는지 모르면 엉뚱하게 깊이 간다. 요청을 구체적으로 쓰는 게 먼저다.

## 비용과의 관계
- 생각한 양도 출력 토큰으로 센다. 높은 effort 를 기본으로 두면 모든 대화가 비싸진다.
- subagent 도 각자 effort 를 가진다. 큰 일을 맡길 때 함께 확인한다. → `subagent.md`

## 흔한 오해
- "effort 높이면 항상 더 좋다" → 단순한 일엔 시간만 더 든다. 가끔 과하게 고민해 일을 키우기도 한다.
- "effort = 모델 바꾸기" → 아니다. 모델은 `/model` 로 따로 바꾼다.

## 1분 실습
- `/effort` 를 입력해 지금 단계를 본다. 바꾸지 않고 Esc 로 닫아도 된다.

## 역할별 예
- 아티스트: 파일 이름 일괄 정리 같은 일은 기본값이나 `low` 로 충분하다.
- Luau 개발자: 타입 오류가 왜 나는지 모를 때 그 질문에만 `ultrathink` 를 붙인다.

## 이해 확인 질문 (설명 뒤 하나만 골라 묻는다)
- 파일 이름 정리에 `max` 를 쓰면 어떤 손해가 있나요?
- 어려운 질문 하나에만 깊게 생각시키는 방법은? (답: `ultrathink`)
