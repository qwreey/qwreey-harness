# qwreey-conventions (plugin development)

Comment, model-doc, copy and structure conventions: path-scoped rules (`rules/`), notice hooks (`hooks/`), skills (`skills/`) and human docs (`docs/`). How it fits together: `docs/how-it-works.md`.

## Where things are
- `hooks/hooks.json`: every hook registration. Main scripts: `conventions-check.py` (added-line checks), `reuse-check.py` + `reuse_sets.py`, `structure-reminder.py`, `rules_inject.py`, `reply_language.py`, `memory-placement.py`, `bash-bypass-reminder.py` (also takes the before-command snapshot), `bash_writes.py` (PostToolUse and PostToolUseFailure on Bash: runs `conventions-check.py`'s `file_notice`, reuse-check and rule injection on the files a Bash command changed). Shared helpers: `conv_env.py` (off and on switches, the plugin's harness.env key defaults, which are also the userConfig defaults in `.claude-plugin/plugin.json`, config dir), `conv_plugins.py` (folders of installed plugins from Claude Code's `installed_plugins.json` and marketplaces; `bash-bypass-reminder.py` and `structure-reminder.py`'s luau-kb planner lookup), `conv_lex.py` (comment lexer, also returns comment column spans and, with `keep_code`, code text), `conv_edit.py`, `conv_docs.py` (model-doc checks: doc kind, checked lines, history markers, skill description, language, ledger paths), `conv_leftovers.py` (Stop report: records and message of old problems left in touched files; `conventions-check.py` re-exports its names and passes it `check_lines` and `invisible_lines`), `layout_metrics.py` (function spans, readable-code metrics and the layout notice text, used by `conventions-check.py` and `conventions-scan.py layout`).
- `scripts/conventions-scan.py`: whole-file `scan` and mechanical `fix` for existing problems (not a hook). It imports the check functions from `hooks/conventions-check.py`, so a check change there changes the scan too; `tests/test-conventions-scan.py` covers it, including the token guard that refuses a fix touching anything outside comments.
- A convention is a rule (`rules/*.md`, everything a model must follow, injected when a matching file is opened or written) plus hook checks whose notices carry the fix; models rarely load a skill a rule points to. A procedure is a user command (`disable-model-invocation: true`, e.g. `skills/comments-cleanup`, `skills/docs-cleanup`) or a skill named for the task. Reference for people (settings, notice tables) goes in `docs/` (`docs/comments.md`, `docs/agent-docs.md`, `docs/code-reuse.md`). `code-reuse` keeps a skill for its procedures (copies across a boundary, regions and sync, library choice); its rule says what must hold, so change rule and skill together. A rule with `switch: KEY` loads only when the harness.env layers give KEY = `on`.
- `README.md` is for people deciding whether to install; technical detail goes in `docs/how-it-works.md`.

## Tests
Run each `tests/test-*.py` with `python3 -I` (exit 0 = pass, no model calls). Also from the repo root: `python3 -I tools/tests/test-vendored-copies.py` (copies) and `python3 -I tools/tests/test-coderag-rules-parity.py` (coderag injects pack rules byte-identically to `rules_inject.py`; needs the coderag binary).

## Rules for this plugin
- `hooks/harness_nonce.py`, `hooks/compact_epoch.py`, `hooks/memory_signals.py`, `hooks/copy_regions.py` and `hooks/known_repos.py` are byte copies of the repo's `lib/`; `hooks/harness_env.py` is a byte copy of `home/.claude/lib/harness_env.py` (the harness.env layer loader). Edit the canon, then run `python3 -I tools/sync-copies.py --apply`; never edit the copies here.
- `rules_inject.py` is the reference that coderag's Rust hook matches for pack rules; a behavior change here needs the same change in coderag and a passing parity test. The `switch:` filter is the one exception: coderag does not read it, so pack rules must not use `switch:` until coderag does.
- The marketplace is a directory source, so installed hooks run live from this folder. Do not move, rename or delete hook scripts while the plugin is enabled.
- Colleagues run an installed copy outside this repo: hooks read only this plugin's folder, `CLAUDE_PLUGIN_DATA`, `CLAUDE_PROJECT_DIR` and Claude Code's own files, never this repo's clone location. Another plugin (luau-kb) is used only when installed (`conv_plugins.py`); without it the hint is left out silently. Check with `HOOK_SANDBOX_PLUGIN_COPY=1 python3 -I tools/tests/test-hook-replay.py`.
- Model-facing hook text follows `home/.claude/HOOK-MESSAGES.md`: English, `<harness-hook ...>` with the session nonce. The Stop report to the user (`systemMessage`) is Korean.
- Hooks never block, except the reply-language Stop rewrite. Notices name only lines the current edit added; old problems are counted for the Stop report, never fixed unprompted.
- `rules_inject.py` and `conventions-check.py` run on every file open or edit, and `bash-bypass-reminder.py` and `bash_writes.py` on every Bash call: standard library only, return early when nothing matches (no write signal means no snapshot and no git call).
