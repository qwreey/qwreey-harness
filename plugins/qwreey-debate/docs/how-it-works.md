# qwreey-debate 동작 상세

구성은 스킬 `qwreey-debate:debate` 하나와 템플릿 두 개(`skills/debate/templates/brief.md`, `synthesis.md`)뿐이다. 훅, 규약 주입, 에이전트 정의는 없다. 모델이 따르는 절차는 `skills/debate/SKILL.md` 에 있고, 여기서는 사람이 알아야 할 구조와 근거를 정리한다.

## 무엇을 위한 것인가
qwreey-advisor 의 검토는 이미 정하거나 생각해 둔 것을 다른 눈으로 보고 놓친 점을 짚는다. 토론은 메인이 아직 따져 보지 않았거나 정하지 못한 점을 다룬다. 토론자가 근거를 직접 조사해(코드, 기록, 웹 검색) 메인이 모르던 것을 가져오고, 지금 안의 약한 근거를 치고, 대안을 내고, 대안마다 각자 장단점을 붙인다. 메인이 정한 이름을 토론에 붙였을 때 나쁜 근거, 다른 대안, 그 대안 각각의 장단점이 분명히 드러났던 꼴이 기준이다.

## 언제 쓰나
- 쓴다: 메인이 둘 이상 사이에서 정하지 못할 때, 첫 생각(메인이 고른 이름, 쓴 초안)을 시험해 보지 않았을 때, 답이 읽어 보지 않은 바깥 사실(생태계 관례, 라이브러리 동작)에 달렸을 때, 사용자가 토론을 권할 때. 대상은 주로 이름, 규약, 매 세션 실리는 문구, 양쪽에 비용이 있는 설계 갈림길.
- 쓰지 않는다: 측정·grep·프로브로 답이 나오는 사실(재서 근거에 넣는다), 사용자가 이미 정한 것, 결함 찾기, 전체 감사.
- 모델 호출 스킬이다. 사용자는 자연어로 권하는 것이 보통이라 description 끝에 "토론 붙여봐", "토론시켜 봐", "찬반 붙여", "debate this" 를 둔다. 대가는 description 한 줄의 상시 로드.

## 흐름
1. 고지: 질문, 두 입장, 모델, 라운드, 대략의 비용을 한 줄로.
2. 입장: 실제 비용이 놓인 축에서 둘. 기본 축은 P 최소(가장 작은 변경, 상시 토큰 최소, 새 장치 없음) 대 Q 넓게(모든 저장소·경우, 검사로 강제). 그 밖에 평문 파일 대 도구 중심, 엄격한 기본값 대 저장소별 선택, 지금 안 유지 대 교체. 메인의 선호는 알리지 않는다(가설을 받은 토론자는 그것을 확인해 오기 쉽다).
3. 브리프(`templates/brief.md`): 같은 글에 입장 문단만 다르다. 공유 근거(경로, 측정치, 흩어졌으면 메인이 쓴 dossier), 사용자 원문, 다시 열지 않을 결정, 읽기 전용, 모든 주장에 파일:줄·명령 출력·URL. 받은 목록 밖으로 더 읽고 웹을 찾으라고 적는다. 답의 꼴: 결론, 지금 안의 약한 근거, 대안별 장단점, 제안 문구 전문, 새로 찾은 근거, 상대 입장에 양보할 것, 사용자만 답할 질문.
4. 언어: 의견서 본문은 사용자 언어, 제안 문구는 그 문구가 쓰일 언어(스킬·rule 은 영어, 기록은 그 저장소 기록 언어).
5. 모델: 문구·설계는 opus, 이름 하나처럼 좁은 것은 sonnet 으로 충분. 둘을 동시에 띄우고 1라운드에서는 서로 보지 못한다.
6. 라운드: 기본 1. 한쪽이 상대 의견서에서 확인할 수 있는 사실(수치, 경로, 측정)로 갈리거나 둘이 더 나은 답의 절반씩을 쥐었을 때만 2라운드(같은 에이전트를 이어서, 상대 1라운드 의견서와 메인의 사실 확인을 준다). 잴 수 있는 갈림은 2라운드 대신 잰다. 재도 갈리지 않으면 사용자가 밝힌 선호를 따른다.
7. 종합(`templates/synthesis.md`): 메인이 한다. 토론자는 투표하지 않는다. 함께 확인한 사실, 둘 다 받아들인 것, 갈림 표(쟁점, P, Q, 고른 쪽과 이유), 대안 표(장단점, 낸 쪽), 적용할 문구, 받지 않은 것, 결과와 무관하게 고칠 것, 사용자 문항. 적용 전에 사용자 언어로 보여 준다.

## 다른 모델 계열(제3 목소리)
- sonnet 과 opus 는 한 계열이라 성향과 맹점을 공유한다. Claude 만으로 토론하면 둘이 같은 데서 함께 놓칠 수 있다.
- 사용자가 다른 계열을 쓸 도구를 갖춰 두었다면(`qwreey-delegate:delegate` 스킬, MCP 서버, CLI) 이름이나 생태계 관례 문제, 메인의 틀 자체가 의심될 때 한 목소리를 더하는 것을 고려한다. 기본은 아니고, 쓸 수 있는데 붙이지 않으면 고지 줄에 그렇게 적어 사용자가 요청할 수 있게 한다.
- qwreey-delegate 에 의존하지 않는다. 어느 도구로 어떻게 부를지는 그 도구의 몫이다. 다른 계열은 지어내거나 과장하는 일이 더 잦아, 인용과 주장을 메인이 확인한 뒤에만 종합에 넣는다.

## 기록
- 사용자가 답한 뒤 `.claude/audit/NN-<주제>/synthesis.md`(다음 빈 번호)에 스냅숏으로 쓴다. frontmatter `format: 1`, `title`, `description`(결론), 스냅숏 머리줄, 입장·모델·라운드·사용자 답 원문 한 줄. 스냅숏은 나중에 고치지 않으므로 답을 받은 뒤에 쓴다. 저장소의 `.claude/README.md` 가 다르게 정했으면 그쪽을 따른다.
- 의견서, 반박, dossier 는 옆의 `raw/` 에 둔다. `raw/` 는 git 무시(`.claude/**/raw/`)여야 하며 없으면 추가한다. 커밋되지 않으므로 종합은 기댄 내용을 경로로 가리키지 않고 인용한다.
- 저장소에 `.claude/audit/README.md` 가 있으면 폴더를 올린다. 결정 자체는 그것이 바꾸는 살아 있는 문서(계획, 결정 기록, 대상 파일)에 들어간다.

## 실패 꼴
- 둘이 같은 답으로 수렴했는데 생태계 grep 이 반증한다. 합의도 확인할 주장이다.
- 의견서가 틀린 수치·경로·출처에 기댄다(엉뚱한 루트를 잼, 경로에서 폴더가 빠짐, 웹 페이지를 잘못 읽음). 종합이 기대는 수치·경로·출처는 모두 확인한다.
- 정해진 결정을 다시 열거나 기각된 안을 다시 낸다. "다시 열지 않을 것" 목록이 대부분 막는다.
- 메인이 한 목소리로 참여하면서 의견서를 먼저 읽는다. 자기 의견을 `raw/` 에 먼저 쓴다.
- 표결이 비기고, 사용자가 다수를 뒤집은 적도 있다. 이유가 정한다.

## 근거
qwreey-harness 저장소에서 실제로 돌린 토론에서 꼴을 정리했다.
- P/Q 토론: `.claude/audit/` 의 25, 26, 29, 31, 38, 41, 48, 49, 50. 48·49·50 은 1라운드로 결정이 났다. 25(judge-run), 26(replay), 29(measure), 31(probes)은 갈림을 2라운드 대신 재서 갈랐고, 25 는 재도 0/10 대 0/10 으로 비겨 사용자 선호를 따랐다.
- 이름 토론(quad 저장소의 `naming-table-review-2026-10-16`, `naming-marker-helper-2026-11-06`, `qa-request/code-quality-review-round15.md`): 메인이 정한 이름의 나쁜 근거, 대안, 대안별 장단점이 분명히 나왔다. codex·Gemini 가 `asState` 로 수렴했지만 메인 grep 이 반증했고, Gemini 가 기각된 안을 다시 냈고, 표결이 6·6·6 으로 비겼다.
- 41 의 1라운드 측정이 엉뚱한 루트를 쟀다가 2라운드에서 상대가 잡았고, 48 은 경로에서 `src/` 가 빠졌다.
- 비용 $1(1라운드)은 2라운드 약 $2 였던 세션 기록에서 어림한 값이다. 다음 토론에서 서브에이전트 원장으로 잰다.
- 설계 초안과 그 이력: `.claude/scopes/plugins/qwreey-debate/archive/research/drafts/debate/`(옛 3계열·2라운드·`/debate` 전용 초안은 `.claude/scopes/plugins/qwreey-delegate/research/drafts/delegate/skills/debate/`).

## 테스트
자동 테스트는 없다(훅·스크립트가 없다). 바꾼 뒤 `claude plugin validate plugins/qwreey-debate` 로 매니페스트와 스킬 frontmatter 를 확인한다.
