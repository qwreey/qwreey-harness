# Q 2라운드 (opus, 2026-11-11)

받은 보고의 요지다. 최종 본문은 verdict.md 에 합쳤다.

## 양보
- worktree 줄과 받아들임/버림 1~3줄을 상시에 둔다.
- choom 문장과 "Opus = 2x Sonnet" 을 지운다.
- 게이트는 혼합안(쓰기는 deny, 읽기는 1회 알림)을 받는다.

## 반박
**(1) allow 와 알림만으로는 첫 쓰기를 막지 못한다.**
PreToolUse 의 additionalContext 는 도구가 실행된 뒤에 결과와 함께 들어온다. 이 세션의 bash-bypass-reminder 가 /tmp 파일이 이미 쓰인 뒤에야 온 것으로 확인했다.

**P 의 게이트는 "로드" 를 강제할 뿐 "승인" 을 강제하지 않는다.**
- 빈 HARNESS_WORKSPACE 일 때 꺼진다는 조건은 거의 발동하지 않는다. harness.env 가 동료 기기에도 복사되기 때문이다(추론).

**(2) 메모리 줄은 상시에 둔다.**
- audit/23 실측 F: "밖: 규칙 로드 안 됨".
- 결론 3: "메모리 경로는 프로젝트 밖이라 rules 의 paths 로는 걸리지 않는다".

**(5) mise 는 조건문 한 줄로 상시에 둔다.**
새 Bash 훅을 두는 비용이 과하다. 꼭 훅으로 하겠다면 기존 Bash 훅에 합친다.

**(6) 상시 분량은 약 0.95k 로 잡는다(2,697B 기준 추정).**

## 게이트 혼합안
| 대상 | 처리 |
|---|---|
| 쓰기: Edit, Write, MultiEdit, NotebookEdit, 그리고 분류기가 쓰기로 판정한 Bash 가 형제 경로를 건드릴 때 | deny(action) |
| 읽기 | compact 회차마다 warn 1회 |

- 쓰기 deny 를 푸는 조건: (세션, agent_id, 회차) 단위로 스킬이 로드되었다는 표시가 있을 때.
- Skill 이 없는 에이전트는 원래 읽기 전용이다. 그래서 쓰기가 막혀도 맞고, 교착도 생기지 않는다.
- 초기화는 compact_epoch 를 재사용한다.
