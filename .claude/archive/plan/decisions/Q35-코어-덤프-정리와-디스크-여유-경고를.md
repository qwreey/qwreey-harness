# Q35. 코어 덤프 정리와 디스크 여유 경고를 어느 플러그인에 둘까?

## 맥락

사용자 요구: "core dump 가 생긴 경우 필요하지 않다면, 의도되었다면 정리하도록. 만일 필요하다고 고려된다면 사용자에게 알릴 것. 명령 실행 전 후로 df 를 뒤에서 돌고, 용량이 위험하다면 경고하도록."

실측(2026-11-19)
- `core_pattern=core`, `core_uses_pid=1`, `ulimit -c unlimited`: 덤프는 죽은 프로세스의 cwd 에 `core.<pid>` 로 떨어짐
- 지금 남은 덤프 약 19 GiB
  - quad worktree `agent-afbfdf8c…` 에 luau-lsp 덤프 10개(13 GiB)
  - `/var/tmp/tsrev` 에 coderag typescript-swc 덤프 10개(6.1 GiB). a736bc8 에서 고친 스택 넘침이 원인으로 보임
- `os.statvfs` 3번에 약 16µs: 따로 프로세스를 띄울 필요 없이 훅 안에서 바로 잼

설계안(공통)
- Bash 앞뒤 훅에서 cwd 의 파일시스템과 /tmp 의 남은 용량을 잼
  - 남은 용량이 10 GiB 미만이거나 5% 미만이면 warn
  - 명령 하나가 2 GiB 넘게 먹었으면 warn
  - 같은 경고는 세션당 한 번만
- 명령 뒤 cwd 에 새로 생긴 `core`/`core.<n>` 이 있으면 action
  - 의도했거나 필요 없으면 지움
  - 필요하면 경로와 크기를 사용자에게 알림
- 기준값은 userConfig, 기본은 켜짐(Q30 b)

## 선택지

- a) qwreey-proc-guard 에 넣기
  명령 앞뒤에서 자원을 지키는 같은 성격의 훅이고, 덤프는 죽은 프로세스가 남김. 플러그인 하나·훅 하나로 끝남
- b) 새 플러그인 qwreey-disk-guard
  choom 을 안 쓰는 사람도 디스크 경고만 따로 켤 수 있음. 대신 Bash 마다 도는 훅이 하나 늘어남
- c) q 의 개인 안전망으로
  q 에 이미 개인 안전망이 모여 있음. 하지만 q 를 깔아야만 쓸 수 있음

**권장 a) qwreey-proc-guard 에 넣기**
이미 Bash 마다 도는 proc-guard 훅에 statvfs 몇 번만 더하면 비용이 거의 없음. 덤프도 프로세스가 죽은 결과라 README 의 '무거운 실행 지키기'와 같은 이야기로 묶임
