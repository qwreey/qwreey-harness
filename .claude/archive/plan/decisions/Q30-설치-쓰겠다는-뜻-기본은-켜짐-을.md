# Q30. "설치 = 쓰겠다는 뜻, 기본은 켜짐"을 원칙으로 두고, 지금 꺼진 옵션 넷을 이렇게 바꿀까?

## 맥락

**사용자 지적**: 플러그인 설치 자체가 쓰겠다는 의사인데, 그 뒤에 또 켜야 할 것이 많아 보이고 false 기본도 있음

**지금 기본이 꺼진 것 (전체 30개 옵션 중)**
- conventions `harness_readable_code`(false): 개인 취향 규약이라 동료에게 퍼지지 않게 일부러 끔(Q16). 켜면 코드 파일을 열 때 약 2.3k자 규약 + 배치 알림
- advisor `harness_review_stop`(false): 턴 끝에 커밋 안 된 diff 가 크면 검토 권고. 커밋 직전 권고는 이미 켜져 있음
- advisor `harness_review_plan`(off): high 등급 저장소에서만 동작(등급은 저장소가 정함)
- sessions `session_log_disable`(false): 실제로는 켜짐이지만 '끄기' 체크박스라 뒤집혀 보임

빈 문자열 기본(경로, 실행 파일, extra/exclude)은 '자동'이라는 뜻이라 문제 없음

**원칙(안)**: 플러그인의 기능은 설치하면 켜진다. 기본 꺼짐이 필요하면 그 기능은 따로 고를 대상이니 별도 플러그인으로 뺀다. 예외는 저장소가 따로 켜야 의미가 있는 것(high 등급처럼)

## 선택지

- a) 원칙 + 넷 모두 권장안대로
  readable-code 는 별도 플러그인(기본 켜짐)으로 빼고, review_stop 은 켜짐, review_plan 은 warn(high 등급에서만 권고), session_log_disable 은 양수 스위치 `session_log`(켜짐)로
- b) 원칙 + readable-code 는 conventions 안에서 켜짐
  나머지는 a 와 같음. 플러그인을 늘리지 않고 기본만 바꿈. 대신 conventions 를 설치하면 취향 규약도 따라옴
- c) 지금대로
  꺼진 넷은 비용이나 취향 때문에 일부러 둔 것

**권장 a) 원칙 + 넷 모두 권장안대로**
readable-code 는 취향이라 끄는 사람이 많을 기능이고, 그런 것이 바로 '골라 설치'의 대상. 플러그인으로 빼면 설치가 곧 켜기가 되어 원칙과 맞음. 나머지 셋은 알림 수준이라 켜도 막히는 일이 없음(plan 의 deny 만 막는데 기본은 warn)
