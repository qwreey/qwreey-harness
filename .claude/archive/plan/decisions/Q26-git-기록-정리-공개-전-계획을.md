# Q26. git 기록 정리(공개 전) 계획을 이대로 적용할까?

## 맥락

**사본에서 끝남(실제 저장소는 안 건드림).** 사본 `/code/.claude/jobs/394d4744/tmp/clone`, 계획 `.../tmp/history-cleanup/plan.md`.

**한 것 (기록 전체, 커밋 393개 모두)**
- table-sim 전용 파일 4개 삭제(인계 2, 메모, 분할안).
- table-sim 의 파일·함수 이름, 줄 수, 내부 경로는 `[비공개 프로젝트 세부 생략]` 이나 "한 게임 저장소의 큰 서버 모듈" 꼴로. luau-kb 문서의 교훈과 수치는 남김.
- "공유" 문구 제거, 동료 평가 문장 4곳을 중립 문구로(예: "작업 환경과 습관이 사람마다 다르다" → "작업 환경과 습관이 사람마다 달라서, 안내 없이는 에이전트가 성능을 내기 어렵다").
- tbox, rbvm, 건강 정보는 그대로. 이름만 나오는 언급과 하네스 비교도 남김.
- 검증: 지운 말 0건, 커밋 수·작성자·날짜 그대로, 시험 결과 원본과 같음.

**대가**
- 커밋 해시가 모두 바뀐다. 커밋 메시지 안 해시는 도구가 새 값으로 바꾸지만, 파일 안 옛 해시 인용 445곳은 그대로라 "옛 해시 → 새 해시" 표(commit-map)를 저장소에 넣고 README 에 한 줄 둔다(외부 감사 때 옛 해시도 따라갈 수 있게).
- 이 세션과 worktree 가 옛 기록 위에 있으므로, 적용은 이 저장소의 세션을 모두 닫은 뒤에 해야 한다.

**적용 방법(제안):** 제가 스크립트 하나(`tools/history-rewrite.sh`: 백업 → 새 사본에서 같은 규칙 다시 실행 → 검증 → 정리본으로 교체 → commit-map 커밋)와 HUMAN_TODO 순서를 만들고, 세션을 닫은 뒤 직접 실행. 그 사이 늘어난 커밋도 함께 정리된다.

**함께 정할 것:** 기록에 옛 `plugins/q-ui/node_modules`(TypeScript 등 135개 파일, 약 25MB, 라이선스 문제는 없음)가 들어 있다. 어차피 해시가 다 바뀌니 같이 빼면 저장소가 가벼워진다.

## 선택지

- a) 적용, node_modules 도 빼기
  스크립트 만들고 세션 닫은 뒤 직접 실행
- b) 적용, node_modules 는 둠
- c) 규칙 고친 뒤
  코멘트로(더 가릴 것 등)

**권장 a) 적용, node_modules 도 빼기**
해시가 어차피 모두 바뀌는 김에 공개본에 필요 없는 25MB 도 덜어 낸다. 실행은 세션 밖에서 해야 안전하다.
