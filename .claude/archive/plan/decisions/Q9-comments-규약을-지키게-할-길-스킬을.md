# Q9. comments 규약을 지키게 할 길: 스킬을 줄여 포인터를 걸까?

## 맥락

**D5 메모(원문):** "다만 그러면 코멘트에 관한 코드 퀄리티가 유지되기 어렵다면 결국 나 또한 코드를 읽기 어렵기에 컨벤션의 도움이 떨어지긴 할것 같기도 하고. 필요했던걸 피하는 모양인건 조금 그래."

**맞는 지적이다.** comments 를 지금 꼴로 둔 이유는 비용(스킬 11.8k자를 코드 쓸 때마다 로드)이었지, 스킬 내용이 필요 없어서가 아니다.

**지금 주석 품질을 받치는 것:** comments rule 본문(why 만, 이력 금지, 문자), 저장소 comment_language 주입(이번에 넣음), 편집 뒤 conventions-check 알림, 켜면 readable-code rule(라벨·문단·문서 주석). 스킬에만 있는 것: 저장소 설정 키, 알림별 대처, 예시, 한국어 어미 등.

**길**
- a) comments 스킬을 둘로 나눈다: 쓸 때 필요한 짧은 본문(약 3k자, 예시 위주)과 설정·알림 대처 참고 파일. 그다음 comments 에도 "Before you write or edit a comment…, load" 포인터를 건다(opus 3/3 로드였다).
- b) 스킬에만 있고 흔한 경우에 쓰이는 사실을 rule 본문으로 옮긴다. 다만 rule 주입은 9,000자 상한까지 424자만 남았다.
- c) D7 원인 조사(실제로 놓친 순간 모으기) 결과를 보고 정한다.

## 선택지

- a) 스킬을 줄이고 포인터
  필요한 걸 피하지 않고 로드 비용을 줄임
- b) rule 본문으로 옮김
  늘 실림, 크기 여유가 거의 없음
- c) D7 조사 뒤 결정
  놓친 순간을 보고 고름

**권장 a) 스킬을 줄이고 포인터**
opus 에서 효과가 확인된 유일한 길(트리거 포인터)을 쓰되 로드 비용을 줄인다. 무엇을 짧은 본문에 남길지는 D7 조사가 끝나면 그 결과로 다듬을 수 있다.
