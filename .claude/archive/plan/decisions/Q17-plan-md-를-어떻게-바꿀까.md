# Q17. PLAN.md 를 어떻게 바꿀까?

## 맥락

**조사 결과(audit 64):**
- 우리 저장소: PLAN.md 45.6 KB, 그중 56% 가 한 절의 날짜별 로그. 어제·오늘 일은 하나도 안 들어감. 이 세션은 PLAN.md 를 0번, 패널을 144번 썼다.
- 형제 저장소도 같다: quad ROADMAP 39 KB(한 번 정리한 뒤 다시 자람), table-sim todos 40 KB(42% 가 끝난 일), coderag todo 절반이 끝난 일.
- 바깥 사례(beads, Backlog.md, Anthropic 장기 하네스 등)의 공통점: 할 일·결정은 항목마다 상태를 붙여 닫거나 옮기고, 설명은 markdown, 경과는 git 에 맡긴다. 에이전트가 문서를 알아서 갱신하리라 기대하지 않고, 갱신을 도구 호출의 부산물로 만든다.

**원인:** 한 파일에 수명이 다른 다섯 가지(목표, 정해진 결정, 실행 로그, 열린 질문, 다음 단계)가 섞였다. 로그가 쌓여 나머지를 덮는다. 열린 질문과 다음 단계는 패널로 갔는데 패널은 git 밖이라 동료와 공유가 안 되고, 커밋 메시지의 "D13 a" 는 저장소 안에서 뜻을 찾을 수 없다(`base/decisions/D-13` 과 이름도 겹친다).

**선택지 요약**
- a: 지금 PLAN.md 를 archive 로 옮기고 짧게 새로 쓴다(목표, 지금 단계, 열린 결정 링크). 정해진 결정은 `base/decisions` 로. 그다음 패널이 결정·단계를 저장소 안 항목 파일(`.claude/plan/`)에 쓰게 바꾼다. 답하면 그 파일이 닫혀 archive 로 간다. 동료는 패널로 쓰고 결과는 저장소 웹에서 읽는다. 패널 결정 번호는 `D-xx` 와 안 겹치게 바꾼다(예: Q17).
- b: a 의 앞부분(나누기)과 "마지막 갱신 뒤 커밋 N개" 알림만. 패널은 그대로.
- c: Backlog.md 같은 바깥 도구(웹 칸반이 장점, 우리 기록 규약·패널과 겹침).

**나머지 도구가 안 맞는 이유:** beads 는 DB 라 diff 어려움, Taskmaster 는 JSON 한 파일 충돌, Claude Code Tasks 는 git 밖이고 지금 모델에선 기본 꺼짐.

## 선택지

- a) 나누고 패널을 저장소 파일로
  갱신이 패널 도구의 부산물이 되고 동료와 공유됨, 1~2일
- b) 나누기와 알림만
  반나절, 패널과 이중 진실은 남음
- c) 바깥 도구(Backlog.md)

**권장 a) 나누고 패널을 저장소 파일로**
알림만으로는 "에이전트가 갱신을 안 한다"를 완화만 한다(이 세션이 증거). 패널은 이미 실제로 쓰이니 그 쓰기를 저장소에 남기면 갱신이 저절로 되고, 회사 동료와도 git 으로 공유된다.
