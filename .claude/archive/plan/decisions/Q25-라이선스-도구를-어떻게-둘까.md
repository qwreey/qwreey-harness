# Q25. 라이선스 도구를 어떻게 둘까?

## 맥락

**조사 결과(`.claude/research/drafts/license-skill.md`):**
- 라이선스 스킬은 레지스트리에 많다(LICENSE 생성, NOTICE 생성, 의존성 감사). 하지만 원문을 받아 오는지 확인된 것이 없고 훅을 주는 것도 못 찾았다. 품질이 들쭉날쭉해 들이기 전에 하나하나 검증해야 한다.
- Anthropic 공식 `claude-for-legal` 의 `oss-review`(의존성 라이선스를 배포 방식별로 분류)는 참고할 만하다.
- 원문은 GitHub 라이선스 API 나 SPDX 공식 데이터에서 받으면 된다(설치 0, Windows 도 됨).

**제안**
1. 스킬(먼저): 사용자와 라이선스·공개 여부·배포 방식을 정하고 주의점을 알림 → 원문을 받아 연도·이름을 채움 → 자리표시가 남았는지, 원문과 같은지 대조 → 필요하면 NOTICE·THIRD_PARTY 항목. "기억으로 쓰지 않는다" 를 본문에.
2. 알림 훅(다음): LICENSE·NOTICE 를 쓰거나, 다른 곳에서 가져온 파일·의존성이 새로 들어오면 출처·라이선스·고지를 확인하라는 한 줄(막지 않음).
3. 의존성 호환 검사는 필요할 때.

**자리:** 새 작은 플러그인 `qwreey-license`(스킬 + 나중 훅). 게임 회사에서 에셋 출처(CC-BY 등)까지 다루면 동료에게도 쓸모.

- b) 스킬과 훅 함께
- c) 기존 것 들여옴
  검증 필요
- d) 나중에

**권장 a) 새 플러그인, 스킬 먼저**
스킬은 작고 이번 같은 실수를 바로 막는다. 훅은 어디서 오탐이 나는지 스킬을 써 본 뒤 정하는 게 낫다.
