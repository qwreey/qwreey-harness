# Q6. comments 를 rule 하나로 두고 스킬은 없앨까?

## 맥락

**사용자 코멘트:** "룰로 가자." / "rule 또는 skill 양측중 택일해야하는거 아닐까"

**근거(audit 62):** comments 스킬 로드 0/79. 지킴은 rule 본문과 편집 뒤 알림이 했다. D11 로 스킬에만 있던 지킬 것(한국어 어미, 문체, 알림 대응)이 rule 로 옮겨지면 스킬에 남는 것:
- 설정 키(`.claude/conventions.json`) → 사람용 문서 `docs/`
- 알림 종류와 고치는 법 표 → 알림 글이 이미 줄과 대체 문자를 줌, 문서로
- 기존 주석 정리(conventions-scan scan/fix) 절차 → 사용자가 부탁할 때만: 사용자 명령으로

**원칙:** 규약 = rule(+훅), 절차 = 명령이나 과제 이름의 스킬, 사람용 참고 = docs.

**같은 질문이 남은 곳:** code-reuse, agent-docs (D11 의 4번, 다음 차례). agent-records 는 이동·보관 같은 절차가 많아 스킬로 남는 쪽.

## 선택지

- a) rule 하나, 스킬 없앰
  정리 절차는 사용자 명령, 설정은 docs
- b) 참고 스킬로 작게 남김
  모델이 설정을 찾을 때 쓸 수 있음

**권장 a) rule 하나, 스킬 없앰**
스킬이 지킴에 쓰이지 않았고, 남는 내용은 사람이 볼 문서이거나 사용자가 부르는 절차다. 둘 다 있을 때 생기는 "어디를 봐야 하나" 혼란도 사라진다.
