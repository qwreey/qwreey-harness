# Q22. 다른 저장소의 내부를 이 저장소 기록에 적지 않게 어떻게 유도할까?

## 맥락

**사용자(코멘트):** 비공개 목록을 harness.env 에 적는 건 유연하지 않음. 의존·상호의존이 없으면 참조할지 더 생각해야 하고, 에이전트에게 확인을 맡기고 모르면 사용자에게 묻게.

**안 1: workspace 상시 줄 하나(항상 실림, 약 300자)**
```
- Before writing a sibling repo's internals (file or function names, code, structure) into this repo's records, check that this repo needs them (a real dependency) and that the sibling is at least as public as this repo (its remote, LICENSE); if unsure, ask the user. Otherwise keep only the conclusion here.
```

**안 2: 안 1 + 알림 훅(모델 비용 0, 걸릴 때만)**
- `.claude/` 아래 기록을 쓸 때, workspace 지도(이미 있음)로 형제 저장소를 찾아 그 저장소 안의 경로가 들어가면 info 한 줄: "이 기록이 형제 저장소 X 의 내부 경로 N개를 적었다: 의존이 있는지, X 가 이 저장소만큼 공개인지 확인하고, 모르면 사용자에게 묻는다."
- 설정할 것 없음. 그 저장소 이름만 지나가는 언급은 잡지 않는다(경로만).

## 선택지

- a) 안 1 + 알림 훅
  쓰는 순간에 확인을 떠올림
- b) 안 1 만
- c) 알림 훅만
  상시 줄 없이

**권장 a) 안 1 + 알림 훅**
판단은 에이전트에게 맡기되, 규칙은 쓰기 뒤에 읽히는 일이 많아(audit 62) 쓰는 순간의 알림이 확인을 실제로 일으킨다.
