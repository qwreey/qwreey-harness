# Q11. D9 를 조사 결과대로 고쳐서 진행할까? (Bash 쓰기 검사 + rule 보강, 포인터는 뺌)

## 맥락

**조사 결과(audit 62, 실제 기록 1,501개, 비용 0)**
- 규약 스킬은 실제 작업에서 거의 안 불렸다: comments 0/79, code-reuse·agent-docs·agent-records 합쳐 3/94.
- 원인은 포인터 문구가 아니었다.
  - 69번: Bash(heredoc, sed)로 써서 rule 도 알림도 아예 안 옴.
  - 71번: rule 이 첫 쓰기 **뒤에** 옴(cat·sed 로 읽고 바로 씀).
  - 포인터가 쓰기 전에 있었는데 안 부른 건 12번뿐.
- 실제로 지키게 한 건 편집 뒤 알림: 42건 중 스킬 로드 1, 바로 고침 약 32.
- 메모 말씀("위반이 나야지만 고쳐진다")이 맞고, 지금은 그게 유일하게 작동하는 길이다.

**D6 메모 답:** 키보드 문자·이력 빼기·언어는 스킬 없이 rule 본문과 알림으로 이미 지켜진다. 빈틈은 Bash 로 쓴 경우뿐.

**스킬에만 있어서 안 읽으면 무너지는 것(comments):** 한국어 어미를 파일에 맞추기, 문체(띠 줄, 대문자 IMPORTANT, 의례어), "이전에는" 같은 서술, 일부러 둔 예외는 보고에 한 번 적기.

**고친 진행안**
1. **Bash 쓰기 검사(가장 큼):** Bash 가 바꾼 파일의 추가 줄에 같은 검사를 돌려 모델에게 알린다.
2. **comments rule:** "Details …: load" 줄을 빼고 그 자리에 세 줄(약 200자, 9,000자 상한 안):
   - `Korean comments keep the file's sentence ending (합니다체 or 한다체).`
   - `No banners, capitals or IMPORTANT for routine notes; skip ceremony words.`
   - `On a notice, fix the named lines; leave a deliberate exception and say so once in your report.`
   그리고 훅의 주석 이력 패턴에 "previously/이전에는" 서술을 더한다.
3. **comments 스킬:** 설정 키·정리 절차·알림 표만 남긴 참고로 줄이고, 포인터는 지식 작업용 한 줄만: "Before a comment cleanup the user asked for, or editing `.claude/conventions.json`, load …".
4. code-reuse·agent-docs 의 스킬에만 있는 것(표시 자리·언어별 꼴, description 꼴, 모델 사이 영어)은 다음 차례로 같은 방식.

원칙: 규약은 지킬 것 전부를 rule 과 훅에, 스킬은 절차·설정 참고.

## 선택지

- a) 1·2·3 진행, 4 는 다음
  지킴이 무너지는 곳부터
- b) 1 만 먼저
  Bash 검사가 가장 크고 문구 변경 없음
- c) 문구를 고친 뒤
  코멘트로 적기

**권장 a) 1·2·3 진행, 4 는 다음**
Bash 검사가 놓친 순간의 40% 를 덮고, rule 세 줄이 스킬에만 있던 지킬 것을 늘 실리는 자리로 옮긴다. 둘 다 있어야 스킬을 줄여도 지킴이 줄지 않는다.
