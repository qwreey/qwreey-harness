# Q57. 동료는 플러그인을 어떻게 받게 되나? (바이너리 자리 토론이 이 답에 갈림)

## 맥락

audit 68 토론(P 플러그인에 싣기, Q PATH 에 깔기)의 두 쪽이 모두 이 답에 따라 안이 갈린다고 인정했다. 공식 문서로 확인한 것:
- claude.ai 조직 배포는 마켓 저장소의 **기본 브랜치만** 읽는다. 소스는 `github`, `url`, `git-subdir`, `./` 만 받는다(`archive` zip 없음). 맨 위 `bin/` 이 있는 플러그인은 거부한다.
- 그래서 조직 배포라면 OS별 ref 도 release zip 도 못 쓴다. 바이너리를 플러그인에 실으려면 기본 브랜치에 커밋해야 한다. PATH 설치는 조직 배포로 밀 수 없다(터미널 단계가 하나 는다).
- 마켓 CLI(`claude plugin marketplace add`)라면 두 안 다 된다. P 는 OS별 release zip, Q 는 PATH 에 한 벌을 깔고 hooks.json 이 이름으로 부르는 안이다.
- 두 쪽 모두 rtk·qx 꼴(`setup` 이 settings.json 에 훅을 적기)은 버렸다. 플러그인 옵션(`CLAUDE_PLUGIN_OPTION_*`)이 settings 훅에는 오지 않고, 이 저장소가 마이그레이션 0006 에서 걷어낸 길이기 때문이다.

## 선택지

- a) claude.ai 조직 배포(또는 Cowork)
  플러그인에 싣는 쪽(P), 기본 브랜치에 OS 별 바이너리 커밋이나 다른 길을 0단계에서 찾는다
- b) 동료가 마켓 CLI 로 직접 설치
  두 안 다 된다. 설치 한 줄(PATH)을 가르쳐도 되면 Q, 아니면 P
- c) 아직 모름, 둘 다 열어 둔다
  지금은 어느 쪽이든 필요한 정리만 하고, 0단계에서 실기기로 재고 정한다

**권장 c) 아직 모름, 둘 다 열어 둔다**
어느 쪽이든 먼저 할 정리(아래)가 같고, 갈리는 사실(Windows 의 .exe 찾기, Cowork 의 PATH)은 실기기에서만 확인된다
