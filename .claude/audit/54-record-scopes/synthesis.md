# 54. 기록 범위(scope) 토론 종합

> Snapshot 2026-11-16. May differ from now; check current files and git log before relying on it.

입장: P 최상위 `.claude/` 하나 안에 범위별 하위 폴더를 비추고 검색 필터로 좁힘, Q 범위마다 `<부분>/.claude/` 를 두고 위로 걸어 찾되 배포 폴더는 `coderag.toml` 매핑. opus 2명, 1라운드. 원문은 대화 기록(c9a9e895)에 있고 `raw/` 에는 브리프와 메인의 사전 견해만 있다.

## 질문
기록(.claude/ 의 audit, research, base, plan)을 부분별 범위로 나누고 최상위에는 공유분만 둘 것인가, 규약이 범위·찾기·검색 기본값·옛 기록 이동을 어떻게 적을 것인가. 사용자: "lang 관련해서 측정 하던것이나 그런 자료 -> 이런건 각자 플러그인 안에 .claude 를 만들든, 위치를 옮겨야하지 않나 싶음 … 실제로 backend/frontend 부분 따로 .claude 폴더를 놓고 각자 필요한 지식을 분배 해놓고, 최상위 .claude 에는 공유되는것만 두는 곳도 있었어. 모든 지식을 한 곳에 모으면 관리가 엄청 어렵더라고 … 이게 지금의 컨벤션에 문제로 쌓인것일 수도 있겠는데."

## 둘이 확인한 사실 (메인이 다시 확인)
- 플러그인 설치는 폴더를 점 폴더째 캐시로 복사한다. vendor 로 복사된 quad 안에 `.claude` 597개 md, 68MB 가 딸려 있다(`devplorer/vendor/quad/.claude`).
- coderag 문서 걷기는 점으로 시작하는 폴더를 건너뛴다(`coderag-mdfm/src/walk.rs:7`), 암묵 설정은 최상위 `.claude` 하나만 본다. 반면 `claude_root` 는 가장 안쪽 `.claude` 를 기록 루트로 잡는다(`coderag-core/src/records.rs:139`). lint·훅은 하위 `.claude` 를 기록으로 보는데 검색은 못 본다.
- `plugins` 는 `.claude/` 아래 기록이 아닌 이름(`records.rs:46`), `packs/<pack>/` 는 하드코딩 특례(`records.rs:103`, q `records_check.py:114`). q `records_check.py` 는 최상위만 본다.
- git 이 추적하는 audit 은 127파일 1.96MB, 6.9MB 대부분은 커밋 안 되는 `raw/`.
- 38 합의 1: 스냅샷은 옮기지 않는다(옮기면 다른 스냅샷 안 경로가 깨지는데 스냅샷은 고칠 수 없어서). 저장소 안 60개 파일, 형제 저장소 8개 파일이 audit 경로를 인용한다(P 측정).
- 가장 큰 주제 섞임은 다른 저장소 주제: audit 37, 43~47, 49 는 coderag 에 관한 기록.
- 공식 문서: 하위 CLAUDE.md 는 그 폴더 파일을 만질 때 로드, 하위 skills 는 lazy load, codex AGENTS.md 는 루트에서 cwd 까지 합침(32KiB 상한), Cursor 는 하위 AGENTS.md 를 부모와 합침. 모두 지시문·스킬이고 기록 저장소 분할 안내는 없다. large-codebases 문서는 하위 CLAUDE.md 가 낡고 흩어진다고 경고한다.

## 둘 다 받아들인 것
배포되는 폴더 안에는 기록을 두지 않는다. lint 와 검색의 루트 어긋남은 어느 안이든 고친다. 다른 저장소 주제는 범위로 못 푼다. 여러 부분에 걸친 기록(audit 약 40%)은 최상위. 팩 특례는 일반화한다.

## 쟁점
| 쟁점 | P | Q | 고른 쪽과 이유 |
|---|---|---|---|
| 둘 곳 | 비추기만(`.claude/areas/<경로>/`), `<부분>/.claude/` 금지 | 옆에 두기 기본, 배포·vendor 는 매핑 | 둘 다 허용(사용자). 배포·vendor 되는 폴더는 비추기, 따로 소유·편집되는 부분은 옆에 두기 |
| 범위 찾기 | 경로 앞부분, 설정 없음 | README 있는 `.claude/` 모으기, toml 매핑, vendor 제외 | 비추기는 경로, 옆에 두기는 README 표식 + vendor·refs·worktrees 제외 |
| 검색 기본값 | 전부 + 범위 꼬리표, `--area` 로 좁힘 | 가까운 범위 + 최상위 | 편집 중인 파일이 있으면 그 범위 + 최상위, 없으면 전부 + 꼬리표. 사용자: 잡음은 겪은 것이 아니라 "생기지 않을까 의심한거였음" |
| 옛 스냅샷 | 옮기지 않음(38) | 이동표로 옮기고 경로 다시 씀(39 방식) | 옮김(사용자). 잘못 놓인 기록을 그대로 두면 찾을 때마다 비용이 들고 기술 부채가 쌓인다 |
| 폴더 이름 | `areas/` | `scopes/` | `scopes/` 쪽(사용자 "scopes 모양도 괜찮은것 같긴 한데", 확정은 구현 때) |

## 사용자 답 (원문)
"잡음을 느꼈다기 보단, 잡음이 생기지 않을까 의심한거였음. 폴더 이름은 글쎄, scopes 모양도 괜찮은것 같긴 한데. 일단 두는 곳 둘 다 허용 괜찮은것 같고, 옛 스냅샷은 정리는 필요하다 생각해. 우리가 실수하거나 간과해서 정리해야한다면 그건 정리하는게 맞는것 같음. 가만 놔둔다는건 archive 문서를 찾는다 할 때 또 비용이 들고 기술부체가 쌓이는거니까."

## 고칠 것 (결과와 별개로)
- coderag: lint·훅 루트와 검색 루트를 맞춘다, `packs/` 특례를 범위로 일반화, 범위 꼬리표와 파일 기준 좁히기.
- q `records_check.py` 가 범위를 본다.
- 38 합의 1 의 "스냅샷은 옮기지 않음" 을 "잘못 놓인 스냅샷은 주인 범위로 옮기고, 이동표로 다른 기록의 경로를 다시 쓴다" 로 바꾼다.
