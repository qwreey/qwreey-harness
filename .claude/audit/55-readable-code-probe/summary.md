# 55. 읽기 좋은 코드 규칙 쓰기 실측

> Snapshot 2026-11-16. May differ from now; check current files and git log before relying on it.

규칙 초안 `.claude/research/drafts/readable-code-wording.md` 의 5줄 rule 과 지표 알림이 에이전트 출력을 바꾸는지 본 실측. 서브에이전트(opus)가 측정하고 메인이 이 요약을 썼다. 원자료 `/tmp/rcprobe/`(커밋 안 함). 합계 USD 17.46(작성 12.29, 판정 5.17).

## 방법
- claude -p 2.1.316, 작성·판정 모두 opus, 임시 `CLAUDE_CONFIG_DIR`, `--setting-sources project`. 프롬프트는 과제만 말하고 스타일은 말하지 않는다.
- A 규칙 없음. B rule(라벨 2~10낱말)을 `.claude/rules/readable-code.md` 로, 세부 절을 `.claude/readable-code-details.md` 로. D 는 B + PostToolUse layout 알림 시제품(`--plugin-dir`).
- 과제: L1 reparent/destroy(같은 제거 루프), L2 검사기 5종 + 공개 check/assert, L3 Circle 을 보고 Rect, P1 Python summarize, E1 빈 줄 없는 40줄 함수에 20줄 기능 더하기. 각 3회, 숨은 시험으로 정확성.

- 해석표 겹침: opus 가 코드 뼈대(시그니처와 주석)만 보고 흐름을 적고, 다른 opus 호출이 과제의 기준 단계 중 몇 개를 말했는지 센다.
- 블라인드 판정(opus, 양쪽 순서): A 대 B 는 B 26/30, A 대 D 는 D 30/30, B 대 D 15:15.
- E1(기존 함수 키우기): A 는 3/3 이 69~76줄 한 덩어리, 끼운 이유 블록도 그대로. B 는 1/3 남음. D 는 알림이 뜬 2회 모두 함수 전체를 문단과 라벨로 고쳤다. 남은 1회는 `python3` heredoc 으로 편집해 Edit/Write 훅이 돌지 않았다.
- L1 은 모든 조건이 도우미를 뽑아 "두 번째 복사에서 도우미" 줄을 시험하지 못했다. L3 형제 순서는 A 도 지켰다(기본 행동). P1 은 A 도 문단을 나눴다.

## 고칠 것
- rule: Luau 는 `---` 라고 명시(B 에서 10/45 가 `--` 이거나 없음). "설계 이유는 선언 위"가 `---` 문서 안으로 읽혔다(호버에 이유가 뜸): 문서와 따로인 `--` 블록이라고 쓴다. 첫 줄 요약이 문장 중간에서 다음 줄로 감김(B 4/15, D 5/14): "첫 문장이 첫 줄에서 끝난다"로. 라벨 자리에 이유 문장이 약 5/88: 함정 메모의 자리를 말한다.
- 알림: "함수의 50% 이상 작성"만으로는 E1 을 못 잡는다. "15줄 이상 키움" 조건이 E1 알림 2건을 모두 냈다. 문서 없음 알림에 `---` 를 명시하고 다음 편집 뒤 다시 본다. `__tostring` 같은 메타메서드는 문서 없음에서 뺀다. Bash 편집 우회는 남는다(45회 중 약 13회가 Bash 로 대상 파일을 만졌다). layout 알림의 거짓 경보는 없었다.

## 한계
판정이 작성자와 같은 계열, 칸당 3회. 기준선이 기존 저장소 측정(91%)보다 약하다(54%): 새로 쓰는 작은 과제에서는 opus 도 짧은 함수는 나눈다. 세부 파일 예시가 L1 과 같은 reparent 라 L1 은 B·D 에 유리. B·D 30회 중 29회가 작은 프로젝트를 둘러보다 세부 파일을 읽어서 B 는 "rule + 스킬"의 상한에 가깝다.
