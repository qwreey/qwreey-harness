# M5 본문 검색 구현과 측정

> Snapshot 2026-11-12. coderag 커밋 `329044c`(debug 빌드)에서 전후를 같은 명령으로 잰 값. 전 = 직전 커밋 `1f234be` 바이너리. 측정 스크립트는 /tmp/m5 에 두고 남기지 않았다.

종합 5번(본문 색인 + 맞은 토큰 하한)을 구현했다. 계획은 round1-Q.md 30-50행, M5 는 138행, 방법은 155행.

## 설계
- **블룸 필터를 골랐다.** gen 때 절마다 자기 몫 본문(하위 절 제외)과 첫 절 앞 본문(절 없는 문서는 전체)의 낱말 키를 블룸 필터로 만들어 `bloom` 필드(base64)로 색인에 쓴다. 낱말 목록은 한글 조사("메타테이블을")에서 맞지 않고 크기도 더 크다. 블룸은 한글을 인접 2글자(bigram)로 다뤄 형태소 분석기 없이 조사에 맞는다. 대가: 오탐, 부분 문자열 불가.
- **키 규칙.** ASCII 는 `_ . : -` 로 이은 덩어리 통째 + `. : -` 마디 + 영숫자 조각을 모두 남긴다(`table.freeze` 는 통째로도 `freeze` 로도, `mt.__index` 는 `__index` 로도 찾아진다). 질의의 `table.freeze` 는 통째 키가 있어야 맞아서 `table` 과 `freeze` 가 따로 나오는 절은 잡음이 되지 않는다.
- **크기.** 항목당 16비트, 해시 11개, 오탐 약 0.05%. 12비트(약 0.33%)로 먼저 재니 절이 수백 개인 팩에서 우연히 맞는 절이 `닫힌 실패`에 2건, 식별자 질의에 1-3건 섞여 16비트로 올렸다.
- **랭킹.** 본문 가중치 1(제목 4-5, 요약 2-3보다 낮고 제목·요약에 못 맞은 토큰만). 읽기 예산(`section_threshold` 8000토큰)을 넘는 절의 본문은 증거에서 뺀다. 빼지 않으면 audit/09 의 60.9k 토큰 절 하나가 어떤 질의에도 상위로 올라와 기록 top-5 바이트가 3배(43KB)가 됐다.
- **하한.** 맞은 토큰이 전체의 60%(올림) 미만이면 결과에서 뺀다. 1토큰은 맞아야 하고 2토큰은 둘 다, 3토큰은 2, 5토큰은 3.
- **버전.** `SCHEMA_VERSION` 1 → 2. 런타임은 프로바이더를 부르지 않으므로 옛 캐시는 그대로 읽되(본문 증거만 빠짐) stderr 에 `coderag gen` 안내를 한 번 낸다. tech-design 11.9 에 적었다.

## 측정 환경
`CODERAG_HOME`·`CODERAG_CACHE` 를 임시 폴더로 격리, 임시 `coderag.toml` 에 luau-kb 를 `[[packs]]` 로 등록, `choom -n 1000 --`, 팩만은 빈 폴더에서 `search --pack luau-kb`, 3계층은 claude-doctor 에서(project + pack). 지연은 7회 중앙값.

## 회귀와 바뀐 동작
- 기록 측정은 나빠지지 않았다. 다만 하한 때문에 토큰이 많은 질의는 결과가 줄어든다(q08: 5토큰 중 3개 이상 맞아야 해서 결과 5건 → 1건, 정답은 그대로 1위).
- e2e 테스트 `global_layer_and_namespaced_ids` 는 3토큰 중 1개만 맞던 질의를 쓰고 있어 하한에서 깨졌다. 두 계층이 각각 2토큰이 맞는 질의(`제네릭 상한`)로 바꾸고 global 문서 설명에 낱말을 더했다.
- 1f234be 의 규칙·훅 코드는 건드리지 않았다. 테스트 전체 통과(core 100, mdfm 25, e2e 7 등).

## 열린 문제
- 하한 비율 60%는 기록 12질의와 팩 질의로만 확인한 값이다. 자연어에 가까운 긴 질의에서 정답이 하한에 걸리는지 질의를 더 모아 봐야 한다.
- 부분 문자열은 못 찾는다(`metatable` 로 `setmetatable` 안 됨). 점으로 이은 식별자의 중간 구간(`a.b.c` 에서 `b.c`)도 통째 키가 없다. 필요하면 camelCase 분해와 인접 마디 쌍을 키에 더할 수 있고 색인은 더 커진다.
- 큰 기록(sessions)이 들어간 project 색인이 +63% 라 지연과 크기가 문제가 되면 sessions·audit 모듈만 bloom 을 끄는 옵션(`options`)이 후보다.
- 8000토큰 초과 절은 본문 검색에서 빠진다. 그런 절 안의 낱말은 grep 이 낫다. 임계값은 `[budget]` 설정을 따른다.
- 팩 캐시는 `coderag gen` 을 다시 돌려야 본문 검색이 켜진다(사용자 쪽 `~/.coderag` 캐시도 마찬가지, 이 작업은 건드리지 않았다).
