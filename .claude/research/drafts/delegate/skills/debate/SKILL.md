# debate — 모델 계열끼리 토론시키고 메인이 실측으로 판정하기

외부 모델 실행은 `delegate` 스킬의 `delegate.sh`(아래 `D`)를 쓴다. 격리, uid, 동시 실행 상한, 수명 주기(run → collect → remove)는 그 스킬을 따른다. 틀은 `templates/`에 있다(`brief.md`, `rebuttal.md`, `ledger.md`).

## 근거: 사용자가 실제로 해 온 세 형식

| 형식 | 사례 | 무엇이 좋았나 / 무엇이 문제였나 |
|---|---|---|
| (A) 같은 질문을 따로 묻고 메인이 표로 대조 | quad `.claude/audit/naming-*-2026-10-15~11-06` (sonnet·luna·Gemini) | 싸고 빠르다. 갈린 항목은 반박이 없어 갈린 채로 남는다. 두 모델이 `asState`로 수렴했지만 메인이 반증한 일이 있다(`naming-marker-helper-2026-11-06/README.md:12-18`). |
| (B) 진영을 정한 입장 → 반박 → 판정 | stl-luau `research/trait-debate/` (2026-10-14), quad `.claude/audit/naming-table-review-2026-10-16/` | 반박 중에 새 안(D3)이 나왔고, 따로 판정한 두 판정자가 같은 안을 골랐다. 판정자가 직접 프로브를 돌렸다. |
| (C) 독립 리뷰 → 진행자가 걸러 후보 목록 → 찬반 라운드 → 판정 | quad `qa-request/code-quality-review-round15.md` | Gemini가 토론 중 자기 신설 제안을 철회했고, 진행자의 줄 번호 오기를 바로잡았다(§1). §6에서는 독립 패스를 원장을 보기 **전에** 돌려 앵커링을 피했다. |

이 스킬은 (A)의 1라운드에 (B)·(C)의 반박 라운드와 실측 판정을 붙인 꼴이다. 모델 간 합의만으로는 결론을 내리지 않는다.

## 맞는 문제, 맞지 않는 문제

**맞는 문제**
- 근거가 양쪽 다 팽팽한 판단. 사용자(2026-10-16): *"지금을 유지할 근거도 팽팽하고, 굳이 그렇게 나올 필요가 없다는 점도 팽팽함"*
- 객관 기준이 드문 판단: 이름, API 모양, 코드 품질의 취향 경계. 사용자(2026-10-16): *"코드 퀄리티는 객관적 기준이란게 드물고 … sonnet/gemini 섞어서 토론 붙이는게 좋을거야"*
- 갈래가 둘셋으로 정리되고, 갈래마다 프로브나 파일:줄로 반증할 거리가 있는 설계 선택

**맞지 않는 문제**
- 전수 감사, 결함 전수 사냥, 대조표. `/audit`의 몫이다. stl-luau 2026-11-04 사용자: *"다른 시선 제공자일 뿐 전체 감사에 쓰는 목적은 아니라서"*. Gemini에게 타입 쌍 전수표를 맡겼더니 결함 0건이었다.
- 실행 한 번이면 답이 나오는 사실 질문. 토론하지 말고 메인이 잰다.
- 결정 이력이 길게 필요한데 브리프에 다 담을 수 없는 판단. codex는 지금 empty 모드만 돈다(`delegate` 스킬, 2026-11-10 시범).
- 사용자가 이미 기각한 갈래를 다시 여는 일. 브리프에 "기각됨, 다시 내지 말 것"을 적는다(quad Elem 토론).

**띄우기 전에** 쟁점, 갈래, 참여 모델, 예상 실행 수를 사용자에게 한 줄로 보이고 확인받는다. 토큰은 사용자 몫이다(2026-10-21 *"지금은 좀 효율적으로 쓰고싶어서"*).

## 절차

작업 폴더는 대상 저장소의 `.claude/audit/debate-<slug>-<YYYY-MM-DD>/`다. 원장(`README.md`)과 각 라운드의 원문을 여기에 둔다.

### 1. 쟁점을 정리한다 (메인)
- 질문 한 문장, 갈래 둘셋(각각 한 단락, 같은 길이로), 판정 기준(사용자 원칙 원문 인용), 기각된 것.
- 정본 경로와 사실을 모은다. 메인이 미리 잰 실측(벤치, 프로브 출력)이 있으면 넣는다.
- 갈래마다 "무엇이 나오면 이 갈래가 틀린 것인가"를 한 줄 적는다. 판정 때 이것을 잰다.

### 2. 같은 브리프를 준다 (1라운드, 독립)
- `templates/brief.md`를 채워 `brief.md`로 둔다. **세 모델에 바이트 단위로 같은 본문**을 준다.
- 브리프는 자기 완결로 쓴다. codex는 empty 모드라 파일을 못 읽는다. 필요한 코드는 줄 번호를 붙여 넣는다(`nl -ba`).
- 실행
  ```bash
  $D run codex debate-<slug>-r1 brief.md --mode empty
  $D run agy   debate-<slug>-r1 brief.md --mode empty     # 파일을 직접 읽혀야 하면 --mode worktree
  ```
  agy empty 모드는 아직 실제로 돌려 보지 않았다(2026-11-10 기준). 첫 토론에서 보고서가 stdout으로 제대로 넘어오는지 확인한다. 안 되면 agy만 worktree 모드로 돌리고, 원장의 "입력" 줄에 입력이 달랐다고 적는다.
  Claude는 Agent 도구로 sonnet 서브에이전트 하나(쓰기 없음). haiku는 쓰지 않는다(판단이 들어가는 일). 메인이 세 번째 시각을 맡아도 되지만, 그때는 메인의 1라운드 답을 **다른 답을 읽기 전에** 파일로 먼저 써 둔다(앵커링 방지, round15 §6).
- 백엔드마다 동시 실행은 하나다. 세 모델은 서로 다른 백엔드라 함께 띄워도 된다.
- 끝나면 각 답을 `r1-<모델>.md`로 옮기고 `collect` → `remove` 한다.
- 메인이 1라운드 답의 **인용 사실을 먼저 확인**한다(파일:줄, 인용 코드). 틀린 인용은 2라운드 자료에 "메인 확인: 틀림"으로 붙인다. 틀린 사실 위에서 토론하지 않게 하기 위해서다.

### 3. 서로 비판하게 한다 (2라운드, 최대 2회)
- `templates/rebuttal.md`를 채운다. 모델마다 따로 만든다.
  - 그 모델 자신의 1라운드 답 원문
  - 다른 두 답 원문. 모델 이름은 지우고 "답 X / 답 Y"로 부른다(stl-luau 판은 역할 이름으로 불렀다. 계열 이름을 보면 그 이름에 대한 선입견으로 읽는다 — 추측).
  - 메인의 사실 확인 결과와 "토론 중 새로 나온 사실"(메인 실측)
  - 할 일: 상대 논거마다 인정 / 반박(근거 필수) / 수정된 최종 입장
- 문구 원칙(quad Elem 토론): *"재반박이 안 되는 지점이 있으면 정직하게 인정하라 — 토론은 이기는 게 아니라 근거를 드러내는 것이다."*
- 외부 모델은 새 실행이라 맥락이 없다. 2라운드 프롬프트는 그 자체로 완결이어야 한다(round15 Gemini 프롬프트 약 50KB의 선례).
- 2라운드 뒤에도 근거가 새로 나오는 갈림만 3라운드로 간다. 상한은 3라운드다.

### 4. 수렴과 이견을 기록한다 (메인)
- `templates/ledger.md` 꼴로 원장을 쓴다. 쟁점마다 `수렴 / 부분 수렴 / 갈림`과, 누가 어디서 입장을 바꿨는지와 그 이유를 적는다.
- 수렴은 정답의 증거가 아니다. 수렴한 항목도 4단계 판정을 거친다.

### 5. 메인이 실측으로 판정한다
- 1단계에서 적은 "이 갈래가 틀린 조건"을 잰다. 프로브, 벤치, 파일:줄 확인, 생태계 용례 검색.
- 판정은 넷 중 하나다: **채택 권고 / 보류 / 기각 / 사용자 결정**.
  - 새 필드·이름·메커니즘·규약은 증거가 한쪽으로 기울어도 **사용자 결정**으로 올린다(`delegate` 스킬 "검증 후 반영" 4).
  - 실측으로 가르지 못한 갈림은 갈래별 평문으로 사용자 문항에 올린다.
- 원장 머리에 "결정이 아니라 재료다"를 적는다. 사용자가 정하면 그 원문을 원장에 덧붙인다.
- 토론에서 나온 결함 주장은 메인이 재현 테스트를 먼저 쓴 뒤에만 고친다.

## 규모와 비용

- 기본은 세 모델 × 2라운드 = 외부 실행 4회(codex 2, agy 2)와 sonnet 2회다.
- codex는 ChatGPT Plus 쿼터라 작다. 2026-11-10 시범에서 저장 코드 질의 한 번이 empty 모드로 38초, 26.6k 토큰이었다. 72KB 브리프 기준이다.
- agy는 쿼터가 넉넉하지만 사용자는 겹치는 실행을 싫어한다(stl-luau 2026-10-20 *"제미니 하나씩 올려줘"*).
- 이름 하나처럼 작은 쟁점은 (A) 1라운드로 끝내고, 갈린 항목만 2라운드로 보낸다.

## 알려진 함정

- Gemini는 "파일을 보지 말라"는 지시를 자주 어긴다(quad `naming-devui-2026-10-20/README.md:3` 외). 입력을 같게 하려면 agy를 empty 모드로 돌린다(빈 디렉터리라 볼 파일이 없다).
- Gemini는 인용을 틀리게 옮기거나 과장하는 일이 잦다. 예: "OnEvent가 커리 꼴로 확정"(round15 §1). 2라운드 전에 메인이 사실 확인을 하는 이유다.
- 다수결은 동률이 난다(6·6·6, `naming-devui-2026-10-21e`). 사용자가 다수안을 뒤집은 일도 있다(10-22).
- sonnet에게 보낸 첫 메시지에서 본문이 빠진 사고가 있었다(`naming-base-2026-10-22/README.md:3`). 보낸 브리프의 바이트 수를 원장에 적는다.
- 같은 모델 계열 둘(sonnet과 opus)은 서로 다른 시각으로 세지 않는다(`delegate` 스킬 "왜").
