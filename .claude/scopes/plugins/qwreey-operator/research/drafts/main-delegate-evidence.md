PLAN 5a "제안(사용자, 2026-11-13)"의 근거 측정. 트랜스크립트는 읽기 전용으로 스트리밍했다. 대상은 메인 세션 5개(quad 3, stl-luau 1, claude-doctor 현 세션)와 서브에이전트 1,379개다(quad 753, claude-doctor 216, stl-luau 159, 그 밖 프로젝트 제외).
가격은 `plugins/q/scripts/subagent_ledger.py` PRICES(목록가, opus-5-5 입력 4 / 캐시읽기 0.20 / 출력 20 USD/MTok).
재생성: `.claude/scopes/plugins/qwreey-operator/research/drafts/raw/` 의 `extract.py`(jsonl -> 슬림 이벤트, `python3 -I extract.py <in> <out>`), `turns.py`, `sub.py`, `cost.py`, `wait.py`, `hook.py`, `growth.py`. raw 는 gitignore 이고 이 머신에만 있다.

## 1. 측정 방법과 한계

- "코드 편집"은 Edit/Write/NotebookEdit(`.md .json .toml .yaml` 제외)과, Bash 로 코드 파일에 쓰는 것(python 헤레독, `cat >`, `sed -i`; 스크래치·probe 제외)을 합친 것이다. 메인은 Edit 보다 Bash 헤레독으로 훨씬 많이 쓴다(quad 375233: Edit 17회, Bash 쓰기는 스크래치 포함 약 1,200회). Edit/Write 만 세면 메인 직접 코딩이 1/10 로 과소 계수된다.
- 줄 수는 `new_string` 또는 헤레독 본문 줄 수의 상한이다(교체 스크립트는 옛 문자열도 센다). 상대 비교에만 쓴다.
- "턴"은 사용자 실입력(task-notification·hand-back 제외)부터 다음 실입력까지. 모든 메인 세션이 Opus 5.5(일부 Fable 5.1)다.

## 3. 맥락 누적의 비용

세션 비용 구성(메인): 캐시 읽기 44~63%, 캐시 쓰기 20~37%, 출력 16~22%. 캐시 읽기 토큰 / 출력 토큰은 207~386 이다.

| 맥락 크기(메인 응답당) | 응답 수 | 읽기/출력 | $/응답 | 읽기 비중 |
|---|---|---|---|---|
| <100k | 164 | 77 | 0.108 | 19% |
| 100~200k | 2,189 | 154 | 0.115 | 30% |
| 200~400k | 6,282 | 256 | 0.125 | 50% |
| 400~700k | 4,802 | 382 | 0.210 | 54% |
| >700k | 1,595 | 515 | 0.321 | 53% |

- 컴팩션 뒤에도 맥락은 130~160k 에서 시작한다(시스템·도구 고정분). 컴팩션 직전은 450~710k. 응답당 비용은 400k 를 넘으면 약 1.7배, 700k 를 넘으면 2.6배다. 컴팩션은 세션당 7~24회(중앙 에폭 150~250 응답).
- 같은 줄 수당 비용(USD / 100줄, 중앙은 건당):

| 줄 범위 | 메인(서브 없음) | 서브 전체 | 서브 sonnet | 서브 opus |
|---|---|---|---|---|
| 100~500 | 1.62 | 1.19 | 0.65 | 1.36 |
| 500~2000 | 0.63 | 0.49 | 0.19 | 0.60 |
| 2000+ | 0.59 | 0.30 | 0.08 | 0.38 |

- 서브 맥락 중앙은 190~360k(메인 430~650k 의 절반 안팎). 서브 건당 중앙 비용은 opus $2.7~4.7, sonnet $1.0~1.4, 큰 구현(opus)은 $13~19(60분, 맥락 500k+까지 큼). 즉 큰 구현 서브는 신선하지만 작지 않다.
- 반사실: 서브 없이 메인이 한 "무거운 턴"(편집 10+, 29개)은 $244 였다. 같은 줄 수를 서브 opus 단가로 하면 $138~170, sonnet 단가면 $54~184. 절감은 약 30~70% 이지만 전체 지출(메인 $2.6k + 서브 $3.4k) 대비 1~3% 다.
- 위임하는 턴의 메인도 싸지지 않는다. 위임 턴 라운드당 $0.170, 메인 직접 코딩 턴 $0.147, 라운드당 새 맥락 4.3~4.5k 토큰으로 같다(위임 턴은 24라운드/턴, 직접은 29). 보고서 읽기·검증·SendMessage 로 메인 맥락은 계속 자란다. 위임의 이득은 메인 라운드 수와 큰 도구 출력이 메인에 안 쌓이는 정도다.

결론: 사용자가 든 비용 근거(캐시 읽기 누적, sonnet 강하)는 맞지만 "대폭 절감"은 아니다. 금액 이득은 sonnet 으로 내릴 때(opus 서브 대비 2~5배, 메인 대비 3~7배. 2000줄 이상 구간 메인은 n=4)에만 크다. opus 수행자가 메인보다 싼 구간은 500줄 이상이다. 100~500줄 opus 서브는 1.36 대 1.62 로 거의 같다.

## 7. 경계 제안

위임한다(하나라도 해당):
1. 코드 파일 3개 이상, 또는 새로 쓸 줄 150 이상(편집 p75 가 8회·309줄, 위 3~8 구간부터 서브 단가가 유리).
2. 빌드·테스트 반복이 3회 이상 예상되거나, 예상 10분 이상(메인 직접 코딩 시간의 88%가 10분 초과 턴).
3. 구현 중 정본·타 코드·외부 문서를 많이 읽어야 한다(맥락이 400k 를 넘으면 응답당 비용 1.7배).
4. 설계를 방금 확정한 직후의 구현(확증편향 회피). 검토는 별도 신선한 서브로.
5. 사용자가 그동안 의논을 이어가야 하는 경우.
모델은 단순 구현·기계적 변경이면 sonnet, 설계 판단이 섞이면 opus. 이 규모에서 sonnet 은 opus 서브의 1/2~1/5 단가다.

메인이 직접 한다(전부 해당):
1. 파일 1~2개, 수정 약 60줄 이하, 테스트 1~2회.
2. 방금 사용자와 정한 결정을 그대로 반영하는 짧은 수정, 문서(`.md`), 설정.
3. 판단·질문이 중간에 필요한 일(서브는 사용자에게 못 묻는다. quad 의 폐기 사례).
4. 서브를 띄우는 데 드는 브리핑이 작업 자체보다 큰 경우.

권고(둘 다 info 리마인더이므로 오탐 비용은 한 줄 읽기):
- 1단계 info: 누적 코드 편집 8회 또는 코드 파일 5개(약 7~14% 턴, 오탐 약 50%). 문구는 "서브에이전트에 맡길 크기인지 판단".

- 줄 수·맥락 크기·테스트 횟수 단독 조건은 편집 수보다 나을 것이 없다(오탐 44~55%). 쓰지 않는다.
- 한계: 오탐률은 사후 라벨 기준의 근사다. "나머지 작업"이 대화형(사용자 질문 대기)이었는지는 구분하지 못했다. 연속 턴("확인. 계속 진행하자")으로 걸친 누적은 측정하지 않았다(턴 경계에서 초기화됨). Bash 헤레독 감지는 정규식이라 우회 가능하다.
