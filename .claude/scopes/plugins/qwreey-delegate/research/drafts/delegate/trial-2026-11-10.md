# delegate.sh 첫 실제 실행 — table-sim, 2026-11-10

사용자가 시범 실행을 허락했다. 대상은 table-sim 한 곳이고, 과제는 읽기 전용 질의 하나다. 백엔드마다 run → collect → remove를 끝까지 돌렸다.

| 백엔드 | 모드 | 결과 | 시간 | 토큰 |
|---|---|---|---|---|
| codex `gpt-6-luna` | worktree | **실패**: 셸이 하나도 안 돎(bwrap). exit 0인데 보고서는 "진행 못 함" | 32초 | 20,001 |
| codex `gpt-6-luna` | empty(코드 72KB를 프롬프트에 넣음) | 성공 | 38초 | 26,647 |

- collect와 remove는 매번 1초 미만이었다.
- 고친 버그는 다섯 개다(§5). 그중 둘은 이번 실행으로 검증했고, 셋은 다음 실제 실행에서 확인해야 한다.
- table-sim 메인 작업 트리, 브랜치, ref, stash는 실행 전과 바이트 단위로 같다(§1).

## 2. 실행 기록

과제 원문: `/tmp/dtrial/prompt-query.md`. 사본은 각 `runs/*/prompt.md`에 있다.
- 저장 코드 로드 경로의 호출 순서를 파일:줄로
- 위험 요소 정확히 3개(실측/추정, 막는 테스트)
- 서버 호출부
- "틀에 갇히지 말 것"

### codex worktree — 실패
```
delegate: 경고 — codex worktree 모드는 미검증(실측은 empty 모드뿐)
exit: 0 / main repo: unchanged / worktree changes: (없음)
report: …/.delegate/report.md (523 bytes)
```
- `stdout.txt`의 원인: `bwrap: No permissions to create a new namespace`(모든 exec에서).
  - 호스트가 `kernel.unprivileged_userns_clone=0`이고 `/usr/bin/bwrap`이 없다.
  - codex 내장 bubblewrap도 무권한 uid 61002에서는 namespace를 만들지 못한다.
  - 그래서 `-s read-only`에서는 `pwd`조차 돌지 않는다.
- 모델의 답: *"보고서에 근거를 적으면 확인하지 않은 내용을 사실처럼 쓰게 됩니다. 셸 실행이 가능한 환경에서 다시 요청해 주세요."* 지어내지 않고 멈췄다.
- **샌드박스를 끈 재실행(`-s danger-full-access`)은 자동 권한 판정이 막았다.** 그 결정은 사용자 몫으로 남긴다(§5-1).

### codex empty — 성공
- 같은 질문이다. 대상 파일 넷(`nl -ba`로 줄 번호를 붙임), 관련 `git grep` 결과와 발췌를 프롬프트에 넣었다. 프롬프트는 72,730바이트다.
- 실행: `run codex trial-query-empty … --mode empty` → exit 0, 38초, 보고서 5,809바이트

### agy worktree — 성공
- 실행: `run agy trial-query …` → exit 0, 568초, `REPORT.md` 27,852바이트
- 과정: 대화 기록상 계획 응답 44번이다. `luau tests/run.luau`를 돌렸다(exit 0이라고 보고).
- 프로브 `probe.luau`를 **worktree가 아니라 자기 HOME의 `brain/<대화>/scratch/`에** 만들어 돌렸다.
  - 과제는 "보고서 외 파일을 만들지 말 것"이었고, 머리말은 "worktree 밖에 만들지 말 것"이었다. 둘 다 어겼다.
  - uid로는 막히지 않는 곳(과제 자신의 HOME)이라 guard의 worktree 변경 목록에도 안 잡혔다.
- 메인 저장소 경로(`/code/Projects/table-sim/`)는 읽지 않았다(대화 기록 grep).

## 5. 고친 버그 (`skills/delegate/scripts/delegate.sh`)

1. **codex worktree 모드에서 셸이 전혀 돌지 않음.** [실행으로 확인]
   - 원인: 무권한 uid에서 bubblewrap이 동작하지 않는다.
   - 수정: codex worktree 모드는 기본으로 거부하고, 이유와 대안(`--mode empty`)을 알린다.
   - `DELEGATE_CODEX_SANDBOX=danger-full-access`로만 열 수 있다. 이때 격리는 uid 하나만 남는다. **사용자 결정 문항이다.**
   - 참고: 초안의 "codex `-s read-only`는 cwd 밖 읽기를 막지 못했다"(quad 실측)는 root로 돌던 때의 이야기로 보인다(추측).
2. **codex worktree 모드에서 보고서 덮어쓰기.**
   - 원인: 머리말은 모델에게 `.delegate/report.md`를 쓰라고 하는데, `-o`(마지막 메시지)도 같은 파일에 썼다.
   - 수정: worktree 모드의 `-o`는 `last-message.md`로 보낸다. 보고서가 비어 있으면 마지막 메시지로 대신한다. collect도 `last-message.md`를 남긴다.
3. **agy empty 모드의 보고서 누락.** [미검증]
   - 원인: empty 머리말은 "마지막 메시지에 답하라"인데, 스크립트는 `.delegate/report.md`를 기다렸다. 이대로면 늘 "report: MISSING"이 된다.
   - 수정: agy empty 모드에서는 stdout을 보고서로 복사한다.
4. **agy 프로브가 사라짐.** [실행으로 확인]
   - 원인: agy는 프로브를 HOME의 `brain/<대화>/scratch/`에 만든다. remove가 HOME을 지우면 "실측"의 근거가 사라진다.
   - 수정: collect가 이번 과제의 대화 디렉터리(`meta.txt`보다 새것)의 `scratch/`와 `transcript.jsonl`을 `runs/<…>/agy/<대화>/`로 남긴다.
5. **사용자의 다른 agy 대화가 과제 HOME으로 새어 들어감.** [미검증]
   - 원인: `cp -r /code/.gemini`가 brain(4개), conversations, history까지 복사했다. 과제 uid가 다른 저장소의 대화 기록을 읽을 수 있었고, HOME이 27M였다.
   - 첫 collect가 그 넷을 `runs/`로 끌고 왔다. 메인이 바로 지웠다(원본 `/code/.gemini`의 것은 그대로).
   - 수정: 복사 뒤 `brain/`, `conversations/`, `annotations/`, `implicit/`, `log/`, `crashes/`, `history.jsonl`, `conversation_summaries.db*`, `jetbox_summaries_proto.pb`를 지운다. 인증, settings, config는 남긴다.
   - 문제가 생기면 `DELEGATE_AGY_FULL_HOME=1`로 옛 동작을 쓴다.
   - **다음 agy 실행에서 인증이 그대로 통하는지 확인해야 한다.** 옛 4벌 스크립트도 같은 문제를 갖고 있다(migration 대상).

## 6. 고치지 않은 것 / 남은 문항

- **codex 실패가 exit 0으로 나옴.** 셸이 막힌 실행도 exit 0이고 "report: … (523 bytes)"로 성공처럼 보인다. 보고서를 메인이 읽으면 드러나므로 스크립트에서는 손대지 않았다.
- **사용자 결정: codex worktree 모드를 열지.**
  - 연다면 `DELEGATE_CODEX_SANDBOX=danger-full-access`를 기본으로 하고, 격리는 uid, 메인 트리 쓰기 불가, pre-push 훅에 맡긴다.
  - 열지 않는다면 codex는 맥락을 다 담은 empty 질의 전용으로 둔다(지금 기본).
- **agy가 "파일을 만들지 말 것"을 어긴 것.**
  - 막을 길은 HOME을 읽기 전용으로 두는 것뿐인데, 그러면 agy가 대화 상태를 쓸 수 없어 돌지 않을 것이다(추측).
  - 그래서 막지 않고 collect로 남긴다(§5-4).
- **임시 파일**: `/tmp/dtrial/`(과제 프롬프트, 실행 로그, 실행 전후 상태, 메인 프로브와 `git archive`로 푼 src)은 기록용으로 남겨 두었다. 지워도 된다.
