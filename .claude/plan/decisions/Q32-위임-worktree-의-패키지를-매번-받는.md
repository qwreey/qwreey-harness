# Q32. 위임 worktree 에 없는 의존 파일(패키지 등)은 어떻게 채울까?

## 맥락

**사용자 지적**: SEED 처럼 '알아야만 쓸 수 있는' 설정은 싫음. 메인을 읽기만 허용하고 모델이 필요한 것을 복사해 가는 게 맞지 않나

**지금 상태(확인)**
- 위임 uid 는 메인 트리를 이미 읽을 수 있음(폴더 755, 파일 644). 쓰기만 못 함
- 그런데 위임 첫머리 글(preamble)이 "원본 저장소는 읽지 말고 worktree 의 같은 파일을 읽어라", "패키지 설치와 네트워크 금지"라고 막고 있음. 원본을 막은 이유: worktree 는 고정된 커밋이고 원본은 커밋 안 된 변경이 섞여 있어 근거가 어긋나기 때문
- 그래서 의존 파일이 필요하면 드라이버가 setup 으로 설치해 주는 구조였고, 실행마다 fetch 가 생김

**왜 처음부터 통째 cp 가 아니라 git worktree 였나**
- 기준 커밋이 분명해야 결과 diff 를 정확히 거둠
- 통째 복사는 gitignore 된 것(비밀 .env, 큰 빌드 산출물)까지 다른 회사 모델 쪽 작업 폴더로 옮김
- worktree 는 git 객체를 공유해 빠름
- 환경 변수 때문은 아님

## 선택지

- a) 메인 읽기 허용, 의존은 모델이 복사
  preamble 을 바꿈: 추적 파일은 worktree 판을 읽되, worktree 에 없는 gitignore 된 의존(luau_packages, node_modules 등)은 원본에서 cp 해도 됨. 설정 없음, fetch 없음. setup 은 원하는 사람만 쓰는 고급 키로 남김
- b) 드라이버가 복사(SEED 설정)
  앞서 제안한 안. 저장소마다 패턴을 알아야 함
- c) 지금대로 setup
  실행마다 fetch

**권장 a) 메인 읽기 허용, 의존은 모델이 복사**
알아야만 쓸 수 있는 설정이 없고, 읽기는 이미 가능한 범위라 새로 열리는 것이 없음. 근거 어긋남은 '추적 파일은 worktree 판'이라는 한 줄로 막힘
