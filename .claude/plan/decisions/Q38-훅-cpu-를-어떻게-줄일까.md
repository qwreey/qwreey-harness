# Q38. 훅 CPU 를 어떻게 줄일까? (Rust 는 걸러짐)

## 맥락

비용은 두 종류.

1. 파일 작업 비용: 54a13a3 로 고침(quad 폴더 훑기 2.36초 -> 0.36초). 남은 것은 캐시로.
2. 프로세스 비용: 훅마다 python 을 띄우는 데 약 34 ms(CPU). 도구 한 번에 Bash 0.44 초, Edit 0.33 초.

최소 시험(`.claude/audit/66-hook-server-language/`), 요청 하나에 드는 서버 CPU

| 경우 | python 서버 | Rust 서버 | 지금 |
|---|---|---|---|
| 조용한 훅 | 57 us | 13 us | 33,786 us |
| Edit 검사 42 KB | 670 us | 130 us | 34,912 us |

- 상주 서버로 바꾸면 python 그대로 50~600 배 줄어듦.
- Rust 로 더 아끼는 양은 도구 한 번에 약 1~2 ms 라 무의미해서 거름(사용자: "만일 유의미하지 않다면 여기서 거르자").
- 남은 설계 거리는 언어가 아니라 데몬 운영: 켜고 끄기, 포트와 인증, 코드 다시 읽기, 데몬이 죽었을 때 막는 훅.

## 선택지

- a) http 데몬(python) 시험: 조용한 훅 하나부터
  비용이 가장 많이 나는 조용한 훅(매 도구마다 뜨는 것) 하나를 옮겨 데몬 켜고 끄기, 죽었을 때, 코드 다시 읽기를 실제 세션에서 본 뒤 넓힘. 막는 훅은 명령 훅으로 남김
- b) 파이썬 다이어트만
  구조는 그대로. 절반쯤 줄고 끝(띄우는 비용은 남음)
- c) 다이어트 먼저, 그다음 데몬
  다이어트로 지금 절반을 줄이고 데몬은 실사용 주간 뒤에. 다이어트 일의 상당수는 데몬으로 가면 필요 없어짐
- d) mod(TypeScript, Claude Code 안)
  데몬 운영 없이 비용 0. 훅 약 20개를 다시 써야 함

**권장 a) http 데몬(python) 시험: 조용한 훅 하나부터**
시험으로 비용이 거의 전부 띄우기에서 나온다는 게 확인됨. 다이어트는 데몬으로 가면 대부분 필요 없어지니, 데몬을 훅 하나로 바로 시험하는 게 일을 덜 버림
