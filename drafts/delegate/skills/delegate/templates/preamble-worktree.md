# 작업 환경 (반드시 지킬 것)

- 너는 git worktree `{{WT}}` 안에서 일한다. 이 디렉터리는 {{KEY}} 저장소의 사본이고, 기준 커밋은 detached HEAD다. **이 디렉터리 밖의 파일을 만들거나 고치지 말 것.** 너는 권한이 낮은 별도 사용자로 돌고 있어서, 밖에는 어차피 쓸 수 없다.
- 원본 저장소 `{{ROOT}}`는 읽지 말고, 이 worktree 안의 같은 파일을 읽어라(같은 커밋이다). 예외는 저장소 루트의 `AGENTS.md`에 적힌 것뿐이다.
- 이 저장소의 진입점은 루트의 `AGENTS.md`다. 자동으로 실리지 않았으면 직접 읽어라. 거기 적힌 정본 문서가 판단 기준이다. 정본에 없는 것을 "확정된 결정"으로 다루지 말 것.
- `git commit`, `git push`, `git stash`, `git reset`, `git checkout`, `git switch`, `git worktree`를 쓰지 말 것.
- 실험으로 파일을 고치는 것은 이 worktree 안에서 허용된다. 메인 세션이 diff를 본다. 고쳤다면 보고서에 무엇을 왜 고쳤는지 적을 것.
- 실행은 항상 `( ulimit -v 4000000; timeout 600 <명령> )` 꼴로 한다. 검사와 테스트 명령은 `AGENTS.md`의 "검사" 절을 따른다. 판정은 **exit code**(0이 통과)이지, 출력의 PASS 줄 수가 아니다.
- Roblox Studio, MCP, 네트워크에서 무엇을 내려받는 명령, 패키지 설치를 쓰지 말 것.
- **최종 보고서는 반드시 `{{REPORT}}` 파일에 한국어로 쓴다.**
  - 맨 위에 기준 커밋을 적는다. `git rev-parse HEAD`로 직접 확인한 값을 쓰고, 입력 문서에 적힌 커밋을 옮기지 말 것.
  - 주장마다 근거를 붙인다(파일:줄, 실행한 명령과 출력). 코드를 인용할 때는 파일에서 그대로 옮긴다.
  - 직접 실행해 확인한 것은 "실측", 코드를 읽고 추론한 것은 "추정"으로 표시한다. 하지 않은 실행을 "실측"이라고 쓰지 말 것.
  - 다 못 한 것은 "미완"으로 적는다.
- 이 저장소의 결정은 사용자가 한다. 너의 제안은 "제안"이지 결정이 아니다. 새 필드·이름·메커니즘·규약을 제안할 때는 그렇다고 적어라. 단정적인 어조("치명적", "강력 반대") 대신 근거와 재현으로 말하라.
