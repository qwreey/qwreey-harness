<harness-hook name="self-match-guard" level="action" nonce="2aa48eea220f">
`pgrep -f "test-x.py"` runs inside a while/until loop. Claude Code runs each Bash command through a shell whose argv holds the whole command line, so the pattern matches that shell itself: the loop never ends. Re-run with `pgrep -x <process name>` (matches the name, not the command line); the bracket trick `pgrep -f "[t]est-x.py"`, whose own text no longer matches (only while the plain text appears nowhere else in the command); or `pgrep -A -f` (procps-ng 4.0.3+, skips the calling shell). To wait for a job, run it with run_in_background and wait for its completion notification instead of polling.
</harness-hook>
