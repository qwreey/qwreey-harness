# D-08. 코드 주석 언어

> **상태: 확정(2026-11-11 사용자: 추천대로).** 4절의 추천안을 채택.

> 작성 2026-11-10.

## 1. 각 프로젝트의 입장

| 프로젝트 | 규칙 | 위치 |
|---|---|---|
| quad | 코드 주석은 영어여도 됨("공식성"). 게시 소스는 사실상 영어 | `quad/.claude/conventions.md:13-16` |
| rbvm | 짧은 설명은 영어, "왜 이렇게 짰나"는 한국어로 길게 | `rbvm/.claude/conventions.md:10-13` |
| stl-luau | 한국어가 지배적(강제 아님). 기존 파일은 그 파일의 언어 | `stl-luau/.claude/conventions.md:10` |
| tbox | **한국어로 작성**(밀도·톤은 기존 파일을 따름) | `tbox/CLAUDE.md:78` |
| table-sim | 한국어 기본, 기존 파일의 언어를 따름 | `table-sim/.claude/conventions.md:37,200` |
| devplorer | 한국어 기본, 기존 파일 언어를 따름, vendor 는 영어 | `devplorer/.claude/conventions.md:19` |
| moonwave-luau | 기존 파일의 언어(`init.luau` 영어, 새 툴링 한국어), 재작성 코드는 Q7 에서 결정 | `moonwave-luau/.claude/conventions.md:16-19` |

공통점은 둘이다. **식별자와 에러 메시지 문자열은 영어**(7곳 모두)이고, **기존 파일은 그 파일의 언어**(5곳 명시)를 따른다.

## 2. 실제 근거

- quad 의 영어 근거는 공개 패키지라 외부 기여자가 읽는다는 것이다. 에러 메시지도 같은 이유로 영어로 정했다(`base/architecture.md:455-461`). [기록, 사용자 결정]
- tbox·table-sim 의 한국어 근거는 "읽는 사람 대부분이 한국어"(table-sim `conventions.md:196-200`)다. tbox 는 근거를 적지 않았다. [서술]
- rbvm 의 혼합은 기존 코드에서 읽어낸 관습이다(`signal.luau` 350~400행). [서술]
- 한 파일 안에서 언어가 섞이면 grep·리뷰 비용이 늘어난다. 이를 직접 잰 기록은 없다. [서술]

## 3. 합의안

### 안 A. 공통 규칙 "파일의 언어를 따른다" + 새 파일의 기본 언어는 프로젝트 rules
- 공통 문장은 이렇다. "식별자·에러 메시지는 영어. 주석은 그 파일에 이미 쓰인 언어를 따른다. 새 파일의 기본 언어는 프로젝트 규칙."
- 프로젝트 rules 한 줄의 예: quad "새 파일 주석은 영어", tbox·table-sim·devplorer·stl "한국어".

| 프로젝트 | 변경량 |
|---|---|
| 전부 | 0. 기존 서술과 모순 없음. 프로젝트 rules 로 옮길 때 한 줄씩 |

### 안 B. 조건부: 공개 패키지 소스는 영어, 그 밖은 한국어
- 게시되는 패키지(`pesde` 게시 대상 `src/`)는 영어, 앱·도구·테스트는 한국어다.
- 다만 tbox(공개 패키지인데 한국어 규칙)와 stl(공개 원격인데 한국어 지배)이 정면으로 바뀐다. 기존 주석 수천 줄과 충돌한다.

## 4. 추천: 안 A

- 7곳이 이미 "기존 파일의 언어를 따른다"에 동의하고 있다.
- 남은 차이는 새 파일의 기본값뿐이라 프로젝트 rules 한 줄로 충분하다.
- 안 B 는 tbox·stl 의 사용자 결정을 뒤집는다.

## 5. 사용자 확인 질문

주석 언어 공통 규칙을 "식별자·에러 메시지는 영어, 주석은 그 파일의 기존 언어, 새 파일은 프로젝트가 정한 언어"로 두면 될까요? 공개 패키지(quad, stl, tbox)의 새 파일 기본 언어를 따로 영어로 맞추고 싶으신지도 알려 주세요.
