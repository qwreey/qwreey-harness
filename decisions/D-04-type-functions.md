  - 다만 모양이 `'CheckA' type function errored at runtime: …:4: <메시지>` 다.
  - 같은 진단이 그 값을 쓰는 다른 줄에도 반복된다.
  - `print` + `types.never` 는 메시지 그대로 한 번만 뜬다.
  - 즉 "안 보인다"가 아니라 "보이지만 지저분하다"이다. stl 규약 ③("0.740·0.742 는 `error` 가 뜸")이 더 정확하다.
  - 옛 서술은 lsp 내장 0.729 시절의 관찰로 보인다. [추정]
- 사용 실적은 이렇다. tbox 는 결과 합성 타입 함수 11개를 공개 API 로 운영 중이다.
  - tbox 의 위험 서술은 `Types.Merge` 가 만드는 테이블 타입이 닫혀 있지 않아 모르는 옵션 키를 못 잡는다는 것 하나다(`packages/tbox/CLAUDE.md:120-121`).
  - quad 가 경고한 체이닝 붕괴는 tbox 가 메서드 체이닝 표면을 쓰지 않아 드러나지 않았을 수 있다. [추정, 미검증]

## 3. 합의안

### 안 A. 3단 규칙(기본 금지 · 진단 허용 · 합성은 실측 조건부)
1. **기본**: 새 `type function` 을 만들지 않는다. `index<>`/`keyof<>` 도 같은 위험군으로 본다.
2. **허용**: 오용을 컴파일 에러로 띄우는 진단 전용(결과 타입을 그대로 통과하거나 팬텀에만 씀). 메시지는 `print` + `types.never` 를 권한다(깨끗한 한 줄).
3. **조건부**: 결과 타입 합성은 (a) 음성 대조군 스파이크로 부작용을 재고, (b) 그 결과를 사용자에게 보인 뒤에만 쓴다. 이미 그렇게 정한 저장소(tbox)는 rules 에서 "합성 허용"으로 override 한다.

| 프로젝트 | 변경량 |
|---|---|
| quad | 0(1·2단과 동일) |
| stl | 페이퍼 03 에 "규약이 대체" 배너 1줄(또는 0) |
| tbox | rules 한 줄 override("이 저장소는 타입 함수가 핵심 API — 바꿀 땐 `test/static` 회귀를 같이") |
| 나머지 | 0 |

### 안 B. 버전 의존 규칙
- 규칙 본문은 짧게 둔다. "타입 함수는 Luau 버전마다 동작이 바뀐다. 쓰기 전에 `luau-types` 스킬의 `type-functions.md` 에서 **현재 핀 버전**의 함정 표를 확인한다."
- 함정 표는 스킬 쪽에 `confirmed: 0.734, 0.742` 열과 함께 둔다.
- 정책 강도(금지/허용)는 각 저장소 rules 가 정한다.

## 4. 추천: 안 A + 안 B 의 "버전 열" 결합

- 공통 rules 에는 1단(기본 쓰지 않음)과 2단(진단 전용 허용) 한 줄만 둔다.
- 3단(조건부)과 버전별 함정 표는 스킬 reference 에 둔다.
- 이유는 넷이다.
  1. 네 입장 모두 "조심"이라는 방향은 같고 강도만 다르다.
  2. tbox 처럼 이미 운영 중인 합성을 공통 규칙이 금지하면 규칙이 거짓이 된다.
  3. 진단 노출 서술처럼 **버전에 따라 이미 낡은 근거**가 있어서 함정 표는 버전과 묶어야 한다.
  4. stl 내부 페이퍼와 규약의 어긋남도 "규약이 대체"로 정리된다.

## 5. 사용자 확인 질문

타입 함수 공통 규칙을 "기본은 만들지 않음, 진단 전용은 허용, 결과 타입 합성은 스파이크로 부작용을 잰 뒤 사용자 승인"으로 하고, tbox 만 "합성이 핵심 API"로 예외를 둘까요? 그리고 stl 의 "쓰지 않는다" 페이퍼(03-tuple)는 지금 규약("주의해서 — 금지 아님")이 대체한 것으로 보면 될까요?

## 사용자 결정 (2026-11-10)

**합의안 수정: '기본은 만들지 않음' 이 아니다.** 사용자 설명은 이렇다.
- 타입 함수는 **부작용과 제약이 많다.** 그 제약이 지금 여러 저장소에 흩어져 있으니 한곳에 모아 정리해야 한다.
- 아예 안 쓰는 것이 아니다. '진단 전용' 이라는 구분도 애매하다. 예를 들어 strip-nil 은 타입 함수 없이는 할 수 없다.
- 판단 기준은 **부작용이 이득보다 큰가, 아니면 이것 없이는 표현이 불가능한가** 다. 그래서 사안별 판단 문제다.
  부작용이 큰 쪽이면 스파이크와 사용자 승인을 거친다.
- 옮길 곳: luau-kb `luau-types/references/type-functions.md` 를 다음 세 가지로 재구성한다.
  1. 제약과 부작용 목록(실측 스니펫 포함, 버전 열 포함)
  2. '타입 함수 없이는 불가능한 패턴' 목록(strip-nil 등)
  3. 판단 절차
